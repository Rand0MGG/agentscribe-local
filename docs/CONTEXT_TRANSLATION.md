# 上下文翻译

在设置 → 翻译模型中选择 `tencent/Hy-MT2-1.8B`，下载 / 检查模型后开始录音。
也可以选择完整本地模型目录。已有 NLLB 偏好不会被替换。

HY-MT2 / GGUF 将初译和最终翻译分开设置：初译默认参考前 1 段，可设 0–2 段；最终翻译默认前 10 段、后 1 段，可设前 0–10 段、后 0–2 段。0 表示不参考。这些设置在下一次录音生效。10 段只作为新安装或缺失配置的默认值；已有偏好（包括 3 段）保持用户保存的数值，用户仍可在设置中修改。

每段首次提交立即进入小上下文初译队列；已经提交但未定稿的原文或语言变化也立即更新请求。只改变时间、稳定范围或版本号，不重复翻译；新邻句或背景变化也不单独触发翻译。原文由 ASR 独立定稿时，捕获当时可用的已定稿前后文，生成一次最终译文。缺少后文不等待。停止录音处理剩余原文并排空翻译队列。

背景只参考已定稿原文，不包含未定稿邻句或旧译文。每段前文最多保留末尾 600 字符，后文最多保留开头 600 字符；待译原文不截断。模型输入超限时先删除最远的前文，再删除最远的后文，并报告背景缩短；完整待译原文自身仍超限则报告失败并保留已有文字。10 段是背景数量上限，不保证所有长段都能装入模型窗口。

模型输入前再次检查背景范围：最多前 10 段、后 2 段，每段最多 600 字符，单段和合并翻译均适用。调用方误传完整录音历史或超长背景时，在构建模型输入、分词或发出模型请求前报错，保留原文和已有译文。背景范围不会随录音总长度增长；设为 0 时不传该侧背景。提示词把背景和本次待译内容分开，并要求只输出待译内容；这些输入边界不替代真实模型的翻译质量验收。

消费者不额外等待凑批：已经排队、字幕位置相邻、语言和翻译阶段相同的内容可以一起翻译。每批最多 4 段，待译原文合计最多 1200 字符；单段过长时仍完整单独处理。批次只带首段之前与末段之后的一份背景，内部各段共享语义信息。批量要求按字幕 ID 返回 JSON 对象，保持原文、时间和译文逐段对应，不把多段译文塞进一条字幕。llama.cpp 使用 JSON schema 约束输出，PyTorch HY 使用提示词及相同解析校验。
模型指令遵循不是形式保证；仍需真实录音评测重复、漏译及上下文带来的收益。

NLLB 保持逐句翻译，上下文选项不可用。它不是指令模型，直接拼接前后文会破坏字幕段落对应关系。

## 实现边界

- `translation_context.py`：提交修订与最终请求快照、冻结上下文、相邻判断及请求有效性，不依赖模型或界面。
- `translation_queue.py`：每段最新请求覆盖、已排队内容的有界合并、队列任务计数。
- `translation_service.py`：串行推理、包含上下文的缓存键，以及发布时整批请求和上下文检查。
- `translation_models.py`：本地模型配置识别、目标语言名称、背景/批量提示词、输出解析和输入预算。
- `backends.py`：NLLB 与 HY-MT2 的独立模型适配器，重型依赖延迟导入。
- `wlk_worker.py`：在字幕状态锁内更新上下文并排队；推理期间不持有字幕锁。

每段排队期间只保留一个最新请求；原文再改或定稿会替换尚未开始的任务。相同原文、语言和上下文复用缓存；不会随着草稿刷新重复翻译整片窗口。未定稿字幕合并保留最早标识，更新合并后的原文请求。若 ASR 明确推翻已定稿原文，或后文纠正最后一条的断句，则开启新的修订周期。

推理中的旧版本不能覆盖新原文；共享推理期间任一成员变化，整批旧结果拒绝发布，仍需翻译的有效成员重新排队。批量返回缺失、重复、额外 ID 或空译文时整批失败，保留已有译文和原文，标记未完成；没有因模型错误自动重试。

界面标明“初译 · 原文已更新”“初译 · 等待最终译文”或“译文已定稿”。`Caption.translation_phase` 与 `translation_source` 随录音保存；旧录音缺少这两个字段仍可读取。未完成的初译在 SRT / 文本导出中带 `[初译]` 标记。

HY-MT2 的 PyTorch 路线使用 Transformers；Apple Silicon 的 GGUF / Metal 路线见 [llama.cpp](LLAMA_CPP.md)。两种适配共用调度，没有升级 ASR 环境。1.8B 官方配置使用 `hunyuan_v1_dense`，标注 Transformers 4.57.6。
模型按用户选择在 CPU 或 CUDA 上加载，CUDA 支持时使用 BF16，否则 FP16；CPU 使用 FP32。两个模型共用 GPU 时仍需实际检查峰值显存和积压。
沿用官方 1.8B 推荐采样参数；PyTorch 单次输出限制 1024 token，输入限制 8192 token；GGUF 的 4096 token 总窗口预留 1024 token 输出。预算处理只缩短背景，不能截断待译源文。
