# 自动更新

目的：用户在应用内完成下载、校验、安装和重启，同时保留录音、模型、偏好及可用旧版本。开发检查、源码合并与产品发行分别进行。

## 选择与安装门禁

- 按平台、架构、最低系统与稳定/beta 渠道选择版本，不用 GitHub 全局最新 Release 代表所有平台。安装版走原生更新器，源码版提示源码更新；版本比较不能按字符串排序。稳定渠道不接收预发布版本；beta 用户应能获得兼容且更新的稳定版，渠道订阅不能把用户永久留在旧 beta。
- 检查独立于模型准备，失败不阻断录音/保存。遵守联网选择，无更新不打扰，手动失败明确可重试；取消后的迟到响应不再提示，重复点击不并发请求。
- 原生检查无论后台/手动、成功/失败均须结束共享状态；进行中再次手动点击显示当前状态。手动检查的进行中/错误反馈可关闭，设置页保留结果；等待用户确认下载或重启的通知保留到主动关闭，重新检查可找回操作入口；回调绑定请求代次。
- Mac Sparkle、Windows WinSparkle/Inno 负责下载、签名校验、安装和重启；共享代码维护业务门禁与启动恢复，不重复实现 Python 程序自替换。
- 用户确认后可在录音期间按许可下载，但不得安装/强停/重启。等待会话结束、保存/导出/迁移/准备完成及相关自有后台释放；失败或未保存则延后解释。
- 取消/失败先完成已有关闭任务，再恢复共享运行环境和可用状态；新请求不能越过关闭过程，旧安装确认不能恢复取消流程。原生回调不跨线程读 Qt 控件。

## 身份、数据与恢复

- 更新产物、标签与来源固定；签名信任、公钥、订阅地址和应用/安装身份稳定。已发布包不覆盖，改变字节需新版本；更新签名不代替系统签名/公证。
- 应用包只读，用户数据和运行环境独立。兼容环境复用，新环境验证后切换；失败恢复需同时考虑应用与环境兼容，模型不因应用版本变化重复下载。
- 安装前复制并校验旧程序，在稳定基础解释器中启动恢复观察器。新版在 Qt 导入前登记进程身份，主窗口显示才确认桌面引导健康；该健康信号不证明推理、音频或全部课件功能可用。
- 程序替换失败与新版启动失败分别处理。只退出身份/创建时间匹配的自有进程，全部退出后原子恢复；归属不明、解释器损坏或无法退出时保留旧备份并提示恢复，不盲目覆盖。失败新包与人工恢复材料保留。
- Windows 升级仅清理旧构建清单中内容未变且新版删除的程序文件；缺清单不猜测，未知/用户文件不清理。卸载/升级不得删除录音、模型或自选目录。
- 旧客户端无法直接接收新格式时先提供可验证的过渡版本；保留旧入口与信任。已发布 beta.2 无应用内安装能力，需要一次手动过渡，不能宣称现在已能自动升级。

## 验收

用正式候选旧包→新包验证：正常下载、取消、断网、篡改拒绝、录音中等待、保存失败、退出清理、安装失败、新版启动失败、环境兼容、数据/模型保留及重启。两端、渠道与架构分别验收，包括 beta→稳定、无更新时静默与取消后的迟到事件；完整包单独启动或隔离 Sparkle 演练不能替代生产升级。
