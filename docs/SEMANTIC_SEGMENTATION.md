# SaT 上下文分句

SaT 是字幕链路必需的本地文本边界模型。运行 `scripts/install_semantic.py`，或在“模型管理 → 字幕与延迟”点击“准备 / 检查 SaT 分句模型”，安装组件并下载权重（约 408 MiB，另有分词器）。准备完成后推理无需联网。分句设备可以选择 CPU 或 NVIDIA CUDA，识别与翻译设备独立配置；macOS 使用 CPU 分句。

会话首先加载 SaT，成功后才继续准备识别链路；所有模型就绪后开始采集。SaT 缺失或加载失败会阻止启动，并提示准备模型。推理异常会报告错误并停止会话，已经显示的原文保留。

macOS / ONNX Runtime 1.30+ 在“准备 / 检查 SaT 分句模型”时另存一份 CPU ORT 图到 `.work/cache/sat-ort/`，约 449 MiB，不覆盖下载的原始权重。之后启动通过 ORT 内存映射直接引用初始化权重，减少加载时的临时复制；分句阈值、分词器和边界规则不变。机制见 [ONNX Runtime 配置定义](https://github.com/microsoft/onnxruntime/blob/v1.30.0/include/onnxruntime/core/session/onnxruntime_session_options_config_keys.h)。

缓存按运行库版本、机器架构和本地权重标识隔离，完成标记在文件写好后才发布。已有安装可重新点击准备按钮生成缓存；开始聆听时只读取缓存，不转换模型。没有兼容的完整缓存、较旧运行库或其他平台沿用原始 ONNX 加载。缓存损坏导致实际载入失败时报告模型错误，可重新准备修复；不把推理错误忽略掉。准备缓存本身需要一次较高的内存峰值，属于模型准备阶段，不能算成聆听启动内存降低。

## 从文本到字幕

1. ASR 持续提供稳定原文和可修订草稿。
2. SaT 根据清理过的文本副本返回字符边界，再映射到原文位置。较长输入通过重叠窗口处理；相同文本复用预测结果。
3. 字幕管理按模型边界生成暂定分段，原样保留字符。首次提交立即排队初译；之后已提交原文变化更新请求，但不锁死错误断点：SaT 随后文撤回断点时允许合并，保留最早一条的标识与已有译文，删除被合并条目，再翻译合并后的原文，后续字幕标识不串位。已经提交的文本不因新增暂定断点反复拆成更多初译任务。
4. 边界内原文达到 ASR 稳定区即可首次提交。没有 SaT 内部边界的稳定尾部，由独立时钟检查首次提交条件，不依赖新文字到来。
5. ASR 完成该段最终解码后，原文独立定稿。翻译速度、是否成功、是否有后文都不参与此判断。停止聆听对剩余文本收尾。

| 状态 | 行为 |
| --- | --- |
| 未提交 | 展示识别内容，等待稳定区与分句或尾部等待条件 |
| 已提交，可修订 | 首次提交和原文变化立即排队小上下文初译，默认参考前 1 段已定稿原文；新结果到来前保留已有译文并标记 |
| 原文已定稿 | ASR 已完成该段；请求一次最终翻译，默认参考前 10 段、后 1 段已定稿原文；相邻待译内容可共享背景合并 |

“稳定尾部首次提交等待”默认 3 秒：尾部已经处于 ASR 稳定区、文本保持不变后，用墙钟计时触发初译，检查周期约 250 毫秒。沿用旧偏好键 `semantic_lookahead` 和已保存数值，但不再表示识别时间戳上的后文长度。它只控制首次提交，不能仅凭时间把原文定稿。

Qwen 快速模式与 MLX 适配均通过同一 `RevisionStore` 的完整原文、稳定范围和 `closed` 标记驱动提交与定稿；PyTorch 准确模式记录完成解码的音频终点。其他 WLK 路线消费 `silence_transcription_ready`，该事件在最终解码及对应快照发布之后到达。裸静音事件不代表识别已经完成。声音输入仍需传递静音 PCM 或显式 EOF，完全断开的输入流不能仅凭没有数据推断结束。

MLX 不再将每次短 VAD 停顿直接报告为完成：保留尚未关闭的音频窗口，恢复说话时加入停顿对应的静音采样，再整体重识别。连续静音的实际 PCM 进度确认超过 3 秒时，才关闭当前话语；没有继续送入音频时，墙钟等待不能关闭它。窗口达到容量上限、明确暂停或会话 EOF 也会关闭相应范围。完成信息进入既有修订存储，字幕与翻译规则保持共用，不另设最少词数或定稿等待时钟。

MLX 使用会话的 `qwen_window_seconds`（默认 30 秒），不再固定为 12 秒；共用适配限制窗口为 8–40 秒，额外边界观察最多 5 秒，MLX 子进程相应接受最多 45 秒 PCM。完整识别结果在转换成上游只追加的词记录前进入修订存储，后文可以修正窗口内的任何词。显式暂停按已接受 PCM 的终点收尾，后续录音不受该结束请求影响。

识别段终点不等于句子边界：句中停顿或模型窗口结束不再强行分行；有明确句末标点时可用识别终点补充分段。逗号、分号、冒号、顿号后的 SaT 候选断点暂不采用。没有后文时，尾段仍可立即定稿并翻译，不恢复无限等待；后文到来后，仅重新检查最后一条没有句末标点的定稿：若 SaT 认为应连读，则重新打开并合并，待整个新段完成后再定稿。这是有界的边界纠正，不扫描重写整篇定稿。

上游明确纠正或末尾断句被后文纠正时允许重新打开已定稿字幕，重新进行翻译周期。每次请求绑定当时的原文快照；原文变化会替换排队中的旧请求，正在推理的过期结果不能发布。等待更新时已有初译可能与当前原文不同，界面明确标记；迟到的初译不能覆盖最终译文。详见 [上下文翻译](CONTEXT_TRANSLATION.md)。

## 能力范围

### SaT 输入副本的标点清理

仅在 `semantic_model.py` 内清理供模型判断的副本，保持大小写和 0.5 阈值。移除普通中英文标点；保护词内撇号、连字符、下划线、数字间小数点、数字前负号，以及常见点式缩写、称谓、HTTP(S) 网址和邮箱。英文词之间缺少空格时用分隔空格替代标点，避免 `hello,world` 粘词；相邻中日韩文字之间不额外插入空格。特殊文本保护是有限规则，不覆盖全部专业记法。

预测位置映射回 ASR 原文，保留原来的词语、大小写和标点；句末标点留在前段，开引号/括号尽量保留在后段。字幕呈现、翻译输入和录音保存仍使用原文片段，不使用清理副本。合并后的句子可能仍含 ASR 的错误句号，此功能不重写标点。

清理对所有输入语言生效。本地英语课堂对照显示部分碎句减少，但中文及合法短句可能过度合并；不能据此承诺整体准确率提升。标点清理沿用上述提交、定稿和 ASR 段终点规则；翻译请求调度见 [上下文翻译](CONTEXT_TRANSLATION.md)。

SaT 只预测文本切分位置，不改写、补全原文，也不恢复 ASR 已经漏掉的词。它不分析音频停顿或说话人轮次，不改变上游识别窗口和音频提交策略。

“Qwen 原文草稿刷新目标”默认 0.5 秒，表示请求频率，实际更新受推理耗时限制；Whisper 保留自己的更新节奏。可修订草稿经过同一字幕映射链路显示。

回归覆盖模型边界、短句、长文本、等待后文、稳定定稿、原文纠正、尾部撤回、字符保留和模型异常。真实课堂的边界质量与端到端延迟仍需使用录音评估。
