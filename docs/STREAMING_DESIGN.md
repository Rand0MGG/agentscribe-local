# 流式处理设计（0.3）

桌面录音持续写入 AudioJournal，喂给独立运行环境内的 WhisperLiveKit AudioProcessor。
音频格式为单声道 16kHz PCM s16le。上游 VAC/VAD 负责连续语音活动处理；不再使用自制 WhisperReviser、能量分段器或 60 秒无法确认就结束会话的逻辑。

Whisper 使用 SimulStreaming/AlignAtt、greedy beam=1。禁用第二套 fast encoder，避免重复下载和同时加载不必要的编码器。Qwen 使用上游 qwen3-streaming windowed 后端，在固定窗口内重算而非重听不断增长的全部录音。

字幕分为稳定原文与可修订尾部。上游最后一行仍可能增长，即使已有句号，也不能锁定整个行；使用上游已提交词的时间戳，按句末或最多约 8 秒拆出确认字幕；不对草稿强行分段。翻译独立消费已确认字幕，失败不会让识别进程因翻译异常终止。

停止：停止录音，排空待处理 PCM，向 AudioProcessor 发送结束标志，处理最终结果和翻译，退出子进程。关闭/取消：终止子进程，删除临时缓冲。每次会话使用新的模型进程，避免上游单例残留旧设置。

Windows 的 Qwen 间接导入 nagisa/DyNet，后者无法读取含中文路径的模型文件。兼容层临时复制真实 nagisa 包和权重到 ASCII 临时目录，使用原始实现，进程退出清理；不替换为假的分词器。

尚需注意：单 GPU 上识别与翻译会竞争资源；独立线程不代表 GPU 内核必然同时运行。连续无停顿讲话也会将已确认词分成短段翻译；实际延迟仍受上游识别提交速度与翻译计算速度影响。
