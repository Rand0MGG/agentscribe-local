# 后台音频处理

选择音频来源后直接开始聆听。应用自动处理模型输入，不再提供音频实验室、处理预设、增强设备或高级参数。录音工作区中的原始录音保存与回听入口保留。

## 当前处理链

48 kHz 单声道采集 → +3 dB 增益与 -1 dB 峰值保护 → 连续重采样到 16 kHz → 语音识别。

- 使用现有 `AudioPipeline`，在推理子进程后台执行，界面线程不加载音频增强模型。
- 增益遇到高峰值时受限，避免放大后削波；不启用自动增益、均衡、传统降噪、WPE 或 DeepFilterNet3。
- 跨输入块保留处理状态；暂停和停止时补齐尾部，继续录音时重新建立处理器。
- 处理只改变送给识别模型的 PCM，磁盘上的录音保留原始采集内容。
- `automatic_audio_config()` 集中维护默认处理，每次聆听生成独立配置快照。旧偏好中的手动增强参数不再读写，旧会话记录仍保留。
- 原声全零会提示来源、静音或权限问题；非法采样明确失败，不能冒充正常识别。

默认链只使用推理环境已有的 NumPy、SciPy 和 soxr，不需要额外准备增强模型。原始音频的声道混合方式保持不变。

### 增益与峰值保护是什么意思

增益是把音频采样值乘以一个系数：+3 dB 约为 1.41 倍，+6 dB 约为 2 倍，+12 dB 约为 4 倍。人声和背景噪声一起放大，并不提高输入的信噪比；是否有利于识别，需要同音频实测，不能只看音量。

数字音频的满幅范围为 -1 到 1。比如某段原本峰值为 0.7，放大两倍后会达到 1.4；直接截到 1 会削平波形。当前峰值保护在每个 10 ms 处理块超过 -1 dB（幅值约 0.891）时缩小整块，峰值过去后逐步恢复增益，避免直接截断，并为后续重采样保留余量。它不是降噪，也不能还原在采集时已经削波的声音。

## 选择依据

2026-10-04 在 Windows / RTX 5070 Ti 上重新比较原声、增益、温和去混响和 AI 降噪，识别统一使用 Qwen3-ASR-1.7B / CUDA / bfloat16。带人工标注的 AMI 固定窗口合计 502 词：原声 111 次词编辑错误，增益和去混响各 108 次，AI 降噪 109 次。60 秒音频中，增益处理约 0.08 秒，去混响约 13 秒，AI 降噪约 21–24 秒。

旧课堂样本的参考是另一识别器输出，未经人工校对：增益与原声相同，去混响比原声少 3 次词差异。这不足以证明更复杂处理有普遍收益。因此默认只保留成本低的增益和峰值保护，不要求用户试听调参。

2026-10-05 补测 +0/+3/+6/+9/+12 dB，AMI 502 词的编辑错误分别为 111/112/108/109/110。+6 是这轮测试档位中最低值，当时据此保留 +6；它比 +9 仅少 1 次编辑，不足以宣称精确或通用最优。原声和 +6 的处理音频及完整识别文本均复现了上一轮结果。

随后使用 GenAI 第五节课 175 秒片段完成五档连续字幕测试，并将原有机器转写纳入并列评价。五份实时稿中主观可读性倾向 +3，+9 接近；+12 与原稿差异最少，但没有保留全部关键术语。用户据此明确选择 +3 dB，自动会话默认随之改为 +3，保留 -1 dB 峰值保护。这是基于当前课堂样本与用户偏好的选择，没有证明 +3 在所有录音上准确率最高；数学符号与分段接缝问题仍需单独处理。

这是一个会议、三个固定窗口及一段课堂音频的文件实验。重叠讲话、窗口边界和参考排序会影响指标；不能把这组数据当作所有场景的准确率保证，也不等同于实时字幕端到端验收。参数、哈希、完整结果与限制见 [音频处理对比记录](testing/AUDIO_PRESET_BENCHMARK.md)。共享链尚待 Mac 实机复核。
