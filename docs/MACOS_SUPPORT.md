## 本轮修改

- **采集缓冲**：Windows 保留 48,000 帧缓冲；Mac 不再强制指定该值，使用 CoreAudio 设备默认缓冲。应用仍每次处理 4,800 帧、48 kHz 音频。SoundCard 会检查硬件缓冲范围，固定的大缓冲可能导致启动失败；依据为 [SoundCard CoreAudio 实现](https://github.com/bastibe/SoundCard/blob/master/soundcard/coreaudio.py)，并核对了本地安装的 0.4.6 源码。
- **取消采集**：已取消的采集在导入音频后端前退出，设备解析后再次检查取消状态。
- **系统声音**：Mac 对 Windows 回环配置提前给出 BlackHole 输入提示；不会把不支持的回环请求传入 CoreAudio。BlackHole 仍作为普通输入使用，本次未安装驱动或调整设备。
- **增强设备**：Mac 音频实验室仅提供 CPU。载入 Windows 的 CUDA 增强配置时转为 CPU，保留增强开关、混合比例等参数；Windows 保留 CUDA 选项与配置。
- **播放初始化**：音频实验室在用户点击回听时才创建 Qt 播放器和输出设备，查看设置或修改参数无需初始化播放后端。
- **安装检查**：Mac 请求 CUDA 增强时，在安装依赖前退出；推理安装器在创建环境前拒绝 Intel / Rosetta Python，提示使用原生 Apple Silicon Python。Mac 的 PyTorch 使用普通 wheel，Windows 仍按 CPU / CUDA 选择指定构建。
- **安装进程**：增强安装器若已经是会话首进程，不再重复调用 `setsid()`。

## 不访问真实音频的测试

```bash
.venv/bin/python scripts/test_no_audio.py -q
```

此入口为当前进程树中的 Python 测试注入 `sitecustomize`，拦截 SoundCard、sounddevice、PyAudio 与 QtMultimedia 的真实导入；模拟模块可正常使用。若发生被拦截的尝试，即使测试捕获异常，入口仍以失败退出。子进程需要继承环境，不使用 `-I` / `-S` 等绕过启动配置的选项。

这是一项针对项目现有音频调用路径的测试保护，不是系统音频沙箱。外部录音程序或直接调用原生 API 仍需人工排除；不要在用户录音期间运行 `smoke_loopback.py`、真实 `smoke_session.py` 或普通应用入口。

## 课堂录音与适配复核（2026-09-30）

检查用户保存的 `xai2`：录音 710.5 秒，80 条字幕，原文和译文全部定稿，没有空字幕、翻译错误状态、翻译原文版本不一致或时间重叠。短于 2 秒的字幕占 13.75%，每条词数中位数 11，时长中位数 4.91 秒。此前 `xai` 相应数值为约 55%、6 词、1.86 秒。两个录音内容不同，这只是字幕形态比较，不能当作同音频准确率实验。技术词误识别和不完整语句仍可见，没有人工逐字参考稿，因此未计算课堂录音 WER。

`xai2` 有 5 条 75–92 毫秒的语气词字幕，包括 `Oh.`、`Okay.`、`Oh, yeah.`。Qwen 时间戳属于估算值；现有保存结果不足以确认它们是实际短语音、错误时间估计还是模型误识别，不自动过滤或改写用户录音。此项仍需带完整识别事件的针对性验证。

本次复核覆盖已有 Mac 改动及本轮修复：

| 范围 | 核查结果与边界 |
| --- | --- |
| 音频采集与回听 | CoreAudio 原生缓冲、提前取消、回环配置拒绝、BlackHole 普通输入、播放器延迟初始化仍集中在原有适配入口；模拟测试通过，未访问真实设备。 |

进一步复现并修复的缺陷：

1. **草稿设置未生效**：MLX 把低于 1 秒的请求间隔强制变成 1 秒。现遵循会话设置；已有按实际推理耗时限制请求频率的逻辑保留。
2. **模型响应可能无限等待**：MLX 的管道读写均无超时。现加载最多等待 180 秒，单次识别最多等待 90 秒；读写堵塞均能结束本会话的识别子进程。重复关闭和处理中关闭有回归测试，强杀后的等待也有上限。
3. **窗口收尾时间可能越界**：较宽草稿缩为较短最终音频窗口时，共有修订存储仍保留超出窗口的前缀估算时间。现将这些估算限制在最终音频区间内；覆盖从 12 秒草稿收尾到 8 秒窗口的复现。正常增长假设仍保持前缀时间稳定。此修复不等于精确词级对齐，也未证明上述 5 条语气词来自这一缺陷。

最新验证：macOS 26.6.2 / Apple M2 / 8GB / arm64 / Python 3.12.14；无音频设备测试 **299 passed**，原生音频导入尝试为零；修改的 Python 文件 Ruff 和差异空白检查通过。完整 Ruff 另有 41 项问题，均位于本次未修改的文件，没有将全库静态检查标为通过。Windows 的平台分支使用模拟测试，尚无 Windows 实机结果。

最新真实文件验证：`xai2` 前 40 秒以 1× 速度送入 Session → AudioJournal → WLK → MLX / Apple GPU → SaT / CPU → HY Q4_K_M / Metal，6 条原文与译文全部定稿，原文版本匹配，无失败，最终字幕文本与完整模型修订记录一致。MLX 分配峰值 2.50 GiB；该数字不是整个进程或系统内存。192 万个 48 kHz 样本完整送达，总会话 55.99 秒，输入结束后约 6.95 秒完成。原生音频守卫全程启用。证据位于 `.work/mac-file-tests/mac-audit-xai2-40s/`，含配置、输入哈希、识别源文件哈希、完整事件、摘要、资源记录及保存会话统计。

上述结果不证明中文、所有课堂噪声、长会话资源稳定性、原生系统音频、设备权限与切换、CoreAudio 暂停恢复或 Windows 实机已验收。
