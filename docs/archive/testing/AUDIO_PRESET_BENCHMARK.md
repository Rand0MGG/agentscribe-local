# 课堂音频处理预设实测

本文保留 2026-09-11 的实验记录，并在末尾补充 2026-10-04 的复测。早期预设建议只针对当时样本；当前应用已移除音频实验室，采用轻微增益与峰值保护的自动后台处理，依据见最新复测。

2026-10-05 清理说明：退役的增强实现、安装器与预设测试脚本已经删除，本文旧命令仅记录实验来源。放弃方案生成的派生音频已清理，文字报告与标注保留；AMI、MacWhinney、SlideSpeech 的评测资料按用户要求保留。当前固定 +3 dB 后台处理及验证见 [音频处理](../../AUDIO_PROCESSING.md) 和 [清理复核](../../VALIDATION.md#2026-10-05-简化音频处理cpu-分句与清理复核)。

2026-09-11：对同一段 289.92 秒课堂录音测试 15 组处理方案，并对 7 组候选以另一种切分长度复测。当时建议这段录音优先使用纯算法预设；AI 降噪版未证明比原声识别更准确。以下参数与结果是历史证据。

## 推荐参数

| 参数 | 课堂实测 · 纯算法 | 课堂实测 · AI 降噪 |
|---|---|---|
| 神经网络降噪 | 关闭 | DeepFilterNet3，混合 50% |
| WPE 去混响 | 开启，混合 25% | 关闭 |
| WPE 其他参数 | taps 10，delay 3，alpha 0.9999 | 不启用 |
| 自动增益 | 关闭 | 开启，最大 12 dB |
| 自动增益其他参数 | 不启用 | 变化速度 3 dB/s，余量 6 dB，噪声上限 -45 dBFS |
| 输出增益 | +6 dB | 0 dB |
| 限幅 | 开启，-1 dB | 开启，-1 dB |
| 传统降噪 / 高通 / 均衡 | 全部关闭 | 全部关闭 |

AI 实测使用 CUDA。应用选择预设时保留当前增强设备；CPU 的速度和数值一致性没有在本轮验证。纯算法预设的音频处理不使用神经网络，后续语音识别仍使用 Qwen。

## 两轮结果

**指标是与另一识别器转写的词差异率，越低越接近该文本，不是真实错误率。参考文本未经人工校对，不能据此宣称准确率提升多少。** 两种切分使用同一录音，属于敏感性复测，不是独立测试集。

| 方案 | 固定 30 秒切分 | 固定 20 秒切分 | 整段处理耗时 |
|---|---:|---:|---:|
| 原声 | 8.59%（53 词） | 8.75%（54 词） | 2.9 秒 |
| 推荐纯算法 | **8.27%（51 词）** | **8.10%（50 词）** | 70.3 秒 |
| 推荐 AI 降噪 | 8.27%（51 词） | 9.40%（58 词） | 101.5 秒 |
| 用户测试前保存配置 | 11.67%（72 词） | 10.70%（66 词） | 100.9 秒 |

纯算法两轮分别比原声少 2、4 个词的差异，收益较小。AI 候选第一轮略好，第二轮略差，不能认定有稳定识别收益。两套候选都比用户之前保存的较强增强配置更接近参考文本。

在本机，纯算法和 AI 预设的处理耗时约为音频长度的 0.24 倍、0.35 倍；耗时包含子进程启动和组件初始化，不包含识别。两者均快于实时，但这里没有测试音频增强与流式识别、翻译同时运行时的延迟和显存占用。

## 2026-10-04 自动后台处理复测

为了移除音频实验室，重新比较四种处理，增加 AMI 官方人工标注样本，避免仅凭旧课堂参考选择默认值。结果采用当前 `evaluation.words` 的 lexical-v1 分词（保留缩写中的撇号）；课堂参考计 609 词，不能直接与旧表的 617 词差异率横向比较。

| 方案 | 课堂词差异 / 609 词 | AMI 词编辑错误 / 502 词 | AMI 每 60 秒处理耗时 |
|---|---:|---:|---:|
| 原声与统一重采样 | 56（9.20%） | 111（22.11%） | 0.01–0.03 秒 |
| +6 dB、峰值保护 | 56（9.20%） | **108（21.51%）** | 0.08 秒 |

| DF3 50%、自动增益、峰值保护 | 54（8.87%） | 109（21.71%） | 20.49–24.49 秒 |

AMI 三个窗口的参考词数为 148、148、206；对应错误分别为原声 20/49/42，增益和 WPE 均为 20/48/40，DF3 为 21/48/40。改按词开始时间排序参考，汇总错误为原声 108、增益/WPE 105、DF3 106，方案排序不变。课堂参考仍未经人工校对，只能称为词差异；AMI 的人工标注指标也受多人重叠和窗口边界影响。

**选择 +6 dB 与峰值保护作为自动后台默认。** 在本轮人工标注样本上，它达到与 WPE 相同的结果，无需加载增强模型，处理成本低得多。3 次编辑的差异很小，不能认定有稳定的泛化收益。WPE 在未校对课堂参考上少 3 次差异，不足以支持默认启用；强降噪更未表现出优势。

### 错误出现在哪一层

1. **公式和专业术语识别是明显障碍。** 同一处 `p theta` 在五份实时稿中成为 `PCI`、`PC time` 等，参数解释又成为 `prior justifi`、`projective time` 或 `project C I`。原稿保留了更容易理解的符号，但也把真实训练数据分布写成 `p theta`。课件明确写出模型 `p_theta(x)` 和样本分布 `p_data(x)`；+6/+9/+12 在介绍训练集的句子中反而保留了后者。课件支持符号的数学含义，不能证明老师当时具体说了什么。
2. **短流式窗口与接缝值得优先排查。** 五档均出现 `real distribution. Fusion of the real world`；它在模型结果事件中约片段第 18.3–18.5 秒首次出现。175 秒整段离线识别、旧热词上下文以及固定 30 秒离线切分均未出现 `Fusion`。控制流式输入后，默认 200 个缓存步长的首次切分在 16.598 秒，将 `real distribution.` 和 `of the real world` 拆开；改成 600 步、不在此处切分时，句子连成 `real distribution of the real world`。但两次短诊断都没有复现 `Fusion`，所以只能确认该切分会破坏这一处连贯性，尚不能断言它是多出 `Fusion` 的完整根因。
3. **这些异常已存在于识别输出。** 五档模型定稿与最终字幕审计全部匹配；本轮没有发现字幕传递丢字或另外添词。句中句号在识别输出中也存在，不能把全部断句问题归咎于后续 SaT 分句。VAD、批次时序、编码窗口与模型本身仍可能共同影响结果。
4. **原稿和多人一致的说法也需要检查。** 六份均写了 `posterior probability`，而课件这一段解释的是给定模型参数时观测数据的 likelihood。可能是口头表述宽泛，也可能是共同误识别；没有人工听校，不能把它直接算作 ASR 错误。口语重复、填充词、数字/符号的不同写法和截取边界，也不能全部视为错词。
