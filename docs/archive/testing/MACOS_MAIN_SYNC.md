# 最新主线的 macOS 兼容性验证

2026-09-29。基线 `ff5bb45`，工作分支 `codex/macos-ui-compat`。本轮验证 PC 端合入的界面、字幕生命周期和 SaT 输入处理在 Mac 上的兼容性。

## 分支与发布

- 本地 `main` 快进到 `origin/main`，从该提交建立短期验证分支。前一轮 Mac 提交 `413b775`、`bf17861` 已包含在主线中。
- 修复与验证记录应通过评审合回共同的 `main`。平台独立发版，不建立长期独立的 Windows / Mac 主线。
- 本轮没有更改版本号或创建发布标签，未进行正式版验收。共享分句策略继续由共同代码维护。

## 环境与限制

M2 / 8 GiB，macOS 26.6.2 arm64，Python 3.12.14，PySide6 6.11.2。原生界面使用 Qt Cocoa，Retina 像素比为 2。

所有验证阻止原生音频后端导入。界面使用独立示例文件库和模拟设备；识别只读取已有文件。没有枚举、采集或播放音频设备，也没有操作用户录音进程。

## 界面修复与验证

新界面的公共样式优先指定 Windows 字体，Mac 启动时出现缺少 Segoe UI 的字体别名扫描提示。Mac 样式现在使用系统自带的 PingFang SC / Helvetica Neue；平台样式集中在 `ui_theme.py`。复测未再出现该字体提示。

- `.venv/bin/python scripts/test_no_audio.py -q`：修改前后均为 **231 passed**，没有原生音频导入尝试。
- 改动文件 Ruff 与 `git diff --check` 通过。
- 原生设置页、模型选择、搜索、弹窗及菜单已生成并检查；普通窗口 1280×840、窄窗口 900×650，以及宽窗口 1600×900。
- 字幕连续更新时平滑跟随、离开底部暂停、圆形箭头返回最新字幕通过原生预览。修复后采样从 1831 经中间位置上升至 1945。
- 原生 `⌘,` 打开设置、`⌘F` 聚焦搜索、`Esc` 返回录音、`⌘N` 打开新建录音弹窗通过；测试取消弹窗，没有创建录音会话。
- 字体调整后的第一次滚动预览与 GPU 回放并行时，固定等待 1.2 秒后的到达底部断言失败；GPU 回放结束后串行复测通过。没有改动滚动算法或扩大断言等待时间，不能据此保证高负载下的动画响应。

证据：`.work/ui-experience/`、`.work/cache/caption-follow/verification.json`、`.work/cache/mac-native-shortcuts/verification.json`。窗口中的设备与字幕为示例。合成滚轮事件和原生窗口预览不等同于实际触控板手势验收。

## Apple GPU 文件识别

沿用固定的 Qwen3-ASR-1.7B 4-bit / MLX 模型、SaT CPU、1 秒草稿目标、1 秒停顿阈值、严格离线、无音频增强，关闭翻译。输入为已有 101.176 秒英文文件，按实时节奏输入。使用原生音频导入守卫、300 秒超时和资源记录；外围内存中止阈值按用户既有授权关闭，应用自己的 MLX 分配上限保持生效。

| 指标 | 结果 |
| --- | ---: |
| 模型和进程准备 | 9.96 秒 |
| 开始输入至首条字幕 | 1.96 秒 |
| 输入结束至收尾 | 3.72 秒 |
| 最终字幕 | 25 段，全部定稿 |
| WER | 0.39%（1 / 256；无词删除或插入） |
| 字幕修订检查异常 | 0 |
| MLX 分配峰值 | 2.41 GiB |
| WLK 计算延后 P95 / 最大 | 2.3 / 3.2 秒 |
| 测试期间系统交换空间增长 | 2598.19 MiB |
| 原生音频访问尝试 | 0 |

此次同时进行过原生 UI 预览，系统交换空间数据包含其他进程，不能全部归因于模型，也不构成受控性能对比。MLX 峰值不包含 SaT、PyTorch、Qt 和系统占用。

证据在 `.work/mac-file-tests/main-ff5bb45-mlx-sat/`，包括配置清单、事件、资源记录和 `summary.json`。真实模型使用最新主线的提交、定稿和 SaT 输入处理；字体修复不改变推理链路。

`At first.`、`They also watched.` 仍单独定稿，上一句尾部 `With different sentences and natural pauses` 仍与下一句合并。这轮通过的是运行兼容性，不能宣称断句质量已改善。标点参与边界筛选与补充的问题需作为共享分句逻辑单独处理。
