# 原架构文档中的验证记录

> 2026-10-15 从工作区架构说明完整保留本节；旧“当前/本次”只适用于其时点。现行方法见 [TESTING](../../TESTING.md)。



界面子进程由 `tests/ui_support.py` 共用退出与日志校验，拒绝 `QPainter` / 绘制效果源错误；测试将 Qt 日志强制写入 stderr，Windows 原生日志中的非 UTF-8 字节以转义形式保留，不因解码失败丢失报错。布局与动效等待有截止时间的实际状态，几何和业务结果断言保持独立。旧偏好解析测试只证明数据兼容，应用会话的固定翻译上下文在两端模拟配置中单独验证。

开发 CI 分为普通无音频回归、课程 SDK 和原生文档渲染。普通回归打印跳过原因；两个专用集成检查安装实际所需组件、预检依赖，并通过 `AGENTSCRIBE_REQUIRE_INTEGRATIONS=1` 将任何选中用例的跳过视为失败。文档渲染使用项目固定版本的独立 Kit，不要求 ASR GPU、不下载识别模型。无权限创建真实符号链接时，只跳过独立的符号链接场景，其他文件保护仍执行；不能用模拟链接证明真实文件系统保护已经验收。

`tests/test_architecture.py` 扫描包内显式导入，检查循环依赖、核心模块的间接 Qt/模型依赖、推理层对桌面的反向依赖，以及实时流程与课程 SDK/worker 的隔离。另有独立 Qt 进程阻止 SDK 导入、模拟课程后台崩溃并验证原文/译文保存。这些约束不替代真实推理测试，也不能识别所有动态导入。

测试覆盖偏好关闭重开、旧配置/损坏配置、退休音频参数忽略、设备恢复、启动校验和失败恢复、收尾状态、活动录音文件锁、最近删除恢复、翻译期间原文修订、翻译加载失败和队列清理。Qt UI 与 QCoreApplication 测试使用独立进程，避免两种应用实例相互污染；核心逻辑直接测试，不加载模型。实际音频处理与识别实验见 [对比记录](AUDIO_PRESET_BENCHMARK.md)。

共享行为对照在真实 PyTorch / MLX 适配器上替换模型端点，向同一 Qwen 流程送入相同假设，比较修订、初译、定稿与迟到译文拒绝；另覆盖取消后的资源关闭、输入/输出管道失败及两端设置往返。这些测试验证公共流程与平台分支，不代替 Windows 硬件或真实模型验收。

2026-09-15 重构验证：完整测试 131 项通过，改动文件 Ruff 通过；使用真实 Windows Qt 窗口生成并检查主界面、设置页和窄窗口预览。示例音频是静音夹具，此验证不代表重新测量了 ASR/翻译质量或 GPU 性能。

当前保留 Windows 窗口材质/拉伸、QSS、ASR 参数、分句与修订算法。它们各有明确职责，本次没有为了搬代码而重写。后续增加业务逻辑时优先放入对应模块；只有跨控件的呈现协调留在 Window，避免再把 Window 作为通用服务传给其他组件。
