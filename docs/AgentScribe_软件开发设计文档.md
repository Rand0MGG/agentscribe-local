# 1. 决策摘要

**保留本地识别、字幕修订、翻译和保存链路；以 DeepSeek API 与一个成熟 harness 的最小兼容验证为选型起点，先交付课件解析和静态术语增强，再加入可修订的来源笔记。** Deep Agents 是优先验证候选，Pydantic AI Harness 是备选；LangGraph 是否显式承载固定业务流程，要依据恢复需求和维护成本决定。不能先建整套图工作流，再到课后阶段验证供应商能否接入。[R2][R15][E1][E2]

目标 3、4 的核心不是“给应用加一个聊天框”，而是建立三个有明确关系的对象：带页码/位置的课程材料、带版本的课堂原文、带证据引用的笔记。框架负责模型调用编排、状态恢复和工具循环；应用仍需负责这些业务对象及其一致性。

| 决策项 | 推荐选择 | 第一版边界 |
| --- | --- | --- |
| 现有实时链路 | 保留 WLK、Qwen/Whisper、SaT、修订与翻译队列 | 云端故障不得影响录音和原文 |
| 可恢复业务任务 | 应用维护来源、任务阶段与原子发布；按需使用框架持久化 | 不把同一状态交给多处独立维护 |
| 现成 agent harness | 先验证 DeepSeek + Deep Agents；必要时比较 Pydantic AI Harness | 只采用一个；不介入字幕提交 |
| 课件解析 | 原生文本优先；用真实材料决定是否需要 Docling | PDF/PPTX 优先；只处理必要难页 |
| 结构化输出 | Pydantic 数据模型 + 代码校验 | JSON 合法不等于内容正确 |
| 检索和存储 | 本地 SQLite + 课程范围检索 | 先不部署独立向量数据库 |
| Qwen 增强 | 共享静态快照 → PyTorch `context` / MLX `system_prompt` | Mac 静态接入提前；动态更新后置 |
| 笔记组织 | 课件大纲 + 已确认原文 + 来源依赖 | 只更新受影响章节，保留用户编辑 |

**最值得立即处理的已有代码问题：** `CaptionMapper.fixed` 为每条定稿字幕保存 `text[:end]`，即累计全文前缀。在稳定字幕数持续增加时，会形成平方级的重复字符串存储。优先消除这个结构性风险，再讨论模型量化和显存技巧。[R5]

**分两次交付产品闭环：** 第一次为导入课件 → 预览与修正术语 → 本地 Qwen 使用静态提示 → 保存生效快照；第二次加入已确认且成功保存的原文 → 合批更新章节笔记 → 点击引用回到材料页或近似录音位置。第一次不必等待整个笔记系统完成。

当前优先完善 macOS，同时保留 Windows。MLX 固定依赖已有静态提示入口，应与 PyTorch 复用一份术语业务实现；平台验收分别记录。首版不包含动态词表、多代理、额外 embedding 模型、省内存模式或通用模型路由平台。[R15][R17][E16]

# 2. 代码审查结论与现有边界

## 2.1 项目并不是从零开始

现有项目是 Windows/macOS 的 PySide6 桌面应用。UI 与重型推理运行库隔离；内部仍保留 `linguaflow` 包名。`.venv-wlk` 和 `.venv-mlx` 分开，避免 WLK 的 Transformers 4 与 MLX 路线的 Transformers 5 混装。新增知识模块不应把它们重新混进一个环境。[R1][R14]

`wlk_worker.py` 负责流式装配；`qwen_accurate.py` 与 `asr_stability.py` 负责两平台共用的识别确认；`wlk_captions.py` 负责字幕边界和重切；`translation_service.py` 已实现计算前和发布前的版本校验。应在这些现有边界上加适配器，而不是替换它们。[R2][R3][R4][R7][R9]

## 2.2 已有能力、缺口与接入点

| 模块 / 证据 | 已有行为 | 本轮建议 |
| --- | --- | --- |
| `qwen_accurate.py` | `model.transcribe(..., context='')` | 将空字符串替换为有界、不可变的上下文快照 |
| `asr_stability.py` | 默认 3 轮、4 秒真实音频进展、保留尾部 4 单元 | 保留安全原则，单独试验延迟策略 |
| `wlk_captions.py` | ASR 与 SaT 双重确认；后续纠正可重新打开旧行 | 提供源文本事件及撤回语义；修复全文前缀复制 |
| `core.Caption` | `revision`、`segmentation_revision`、双重 final 字段 | 新模块不得只判断 `final` 或只按字幕 ID 去重 |
| `wlk_worker.py` | 向桌面发送 caption 快照；处理 audio/pause/stop | 在外部消费事件；动态词表需增加协议消息 |
| `mlx_asr.py` / `mlx_asr_worker.py` | 应用尚未传静态提示；固定 `mlx-audio==0.5.6` 已有 `system_prompt` / `hotwords` | 首批适配静态快照，实际 Apple GPU 质量与资源验收仍待完成 |
| `recording_save.py` | 冻结全量字幕快照、串行写入、合并待保存任务 | 保留快照安全性，减少不必要的全量复制 |
| 本地工作区 | WAV、TXT、SRT、`session.json`，无中央数据库 | 以伴随目录新增知识数据，旧录音仍可读取 |

以上来自所审查的固定提交，而不是根据旧版项目介绍推测。[R3–R10][R12]

特别注意：当前版本已经删除 APM、WPE、DeepFilterNet3 等音频增强实验，只保留后台增益、峰值保护与重采样。本次不把“卸载降噪模型”列作新增优化，也不重新引入这些组件。[R14]

## 2.3 已有测量应如何解读

2026-10-06 的验证记录包含一次约 101 秒固定英文文件的双语链路：Qwen 1.7B / CUDA、HY 1.8B / CUDA、SaT / CPU，开始到就绪 5.187 秒，开始到首条原文 9.453 秒，开始到首条译文 24.593 秒，停止后收尾 10.121 秒，PyTorch 显存分配峰值约 7.54 GiB。该记录还报告 20 条字幕完成定稿、固定 256 词对照 WER 为 0。[R11]

这些数值不能解释为一般课堂准确率、所有硬件性能或两小时会话上限。仓库明确标注了素材和硬件范围，部分本地 `.work` 证据未上传。本次只能确认记录内容，不能独立复核这些原始产物。

同日 40 秒课堂片段对照记录中，工作进程树 RSS 峰值约 5.18–6.93 GiB；复用进程的 CUDA 峰值可能包含先前运行。后续必须统一“开始点击”“模型就绪”“对应语音结束”等计时基点，并重置每会话峰值。[R11]

# 3. Harness 与现成项目选型

## 3.1 哪部分真正需要 harness

固定的课件处理步骤、字幕版本失效规则和数据库事务不应由模型临时决定；它们适合确定性工作流。用户提出“结合整学期材料整理复习计划、寻找遗漏概念、回答课后问题”时，任务路径才需要模型自主选择检索工具、分解问题和整理中间产物。

用户此前明确提出 DeepSeek API 与成熟 harness；本设计保留这个方向，不从零自写 agent 循环。业务领域层负责术语、来源版本和笔记一致性；选定 harness 负责自主工具调用与长任务上下文。Deep Agents 建立在 LangChain / LangGraph 之上，但采用它不等于应用每个固定流程都必须另写一张 LangGraph 图。[E1]

## 3.2 候选比较

下表的“适配结论”是针对 AgentScribe 的工程判断，不是第三方性能排行榜。

| 项目 | 官方能力与定位 | 对本项目的判断 |
| --- | --- | --- |
| Deep Agents + LangGraph | 文件上下文、压缩、子任务、人类审批；底层图状态与检查点 | 优先验证候选。用 DeepSeek 和最小受限工具实测后决定；图编排另评估 [E1–E4] |
| Pydantic AI Harness | 官方能力组合库；类型化 agent、记忆、规划、子代理、步骤持久化 | 备选；候选不通过或集成成本过高时比较同一任务，不并行引入 [E5][E13] |
| OpenAI Agents SDK | 工具循环、handoff、guardrail、会话、追踪，提供 sandbox agent 能力 | 可用，不等于只支持单一模型；但本项目仍要另设计事件驱动的业务工作流 [E6] |
| Claude Agent SDK | 提供 Claude Code 的工具执行与上下文能力，SDK 驱动相应运行进程 | 适合以 Claude 为中心的完整助手；对现有多供应商桌面旁路需求，集成边界更重 [E7] |
| Hermes Agent | 完整个人助手，含记忆、技能学习、多渠道入口、工具和计划任务 | 不首选嵌入。已有桌面 UI、录音会话和文件库，再接入另一套助手产品会增加边界协调 [E8] |

Pydantic AI 已有正式的 Harness 项目，不能简单说它“只有结构化输出、没有 harness”。其文档明确 0.x 的能力 API 可能在小版本间调整，需要锁版本和兼容测试。任何最终采用方案都同样需要固定版本，不能跟随文档示例自动升级。[E5]

## 3.3 选型验证与采用方式

先用同一小份材料完成一次“读取来源块 → 返回带引用术语或整理草稿”的受限 agent 任务；检查实际工具清单、模型适配、结构化输出、流式结果、取消、超时、限流、恢复和用量。记录实际依赖版本与资源成本。这是框架选型验证，不要求首版开放课后 agent UI；真实云调用应在相应材料与凭据已授权后进行。

Deep Agents 通过验证且集成成本可接受时，复用其模型适配和受限工具；未通过则定位兼容问题或比较 Pydantic AI Harness，不同时维护两套框架。固定解析、事务和来源失效规则继续用清楚的函数与任务状态表达，不为它们再写 agent 执行循环。

只有流程确有跨启动恢复、人工中断或多步骤失败续跑需求，且 LangGraph 能减少现有任务恢复代码时，才显式采用图编排。用一个包含中断和恢复的真实任务比较必要代码、持久化数据和维护位置；不能仅凭框架功能表判定收益。无需购买托管部署服务来运行本地工作流。[E1][E2]

如采用 LangGraph 持久化，本地 SQLite checkpointer 是可用起点；它不能替代业务事务和来源校验。首版不部署 Postgres 或多租户服务，也不自制 checkpointer。[E2]

框架复用的部分：执行循环、工具调用协议、检查点、受控中断、上下文管理。仍需自己写的部分：课程材料格式、术语选择、字幕版本适配、笔记引用及撤回、桌面 UI、存储迁移。这些是产品业务，不是“重新写一个 harness”。

## 3.4 文件解析项目不能与 harness 混为一谈

| 项目 | 适合承担什么 | 不应假设它自动解决什么 |
| --- | --- | --- |
| Docling | PDF/PPTX 等结构化解析、阅读顺序、表格、统一文档表示 | 不保证所有公式/图表无误；仍需按页核验与必要的视觉补全 [E9] |
| MarkItDown | 轻量文件转 Markdown，按需安装格式依赖 | Markdown 不自动成为完整的来源坐标模型；不应直接接受任意 URL/压缩包 [E10] |
| LangExtract | 从文本提取带原文位置的结构化信息 | 不是 PDF 渲染器，也不是通用 agent harness；无法定位的抽取仍要拒绝 [E11] |

默认先保留 PDF 页或 PPTX 幻灯片的原生文本和来源位置。使用真实课件比较轻量直提与 Docling 的遗漏、阅读顺序、表格/公式可用性、耗时、峰值内存和安装成本；仅在结构质量收益足以承担依赖成本时采用 Docling。每种材料只选择一条已验证解析路线，不全量双跑 Docling 与 MarkItDown，也不为首版同时集成三套抽取接口。视觉补全限必要页；无法可靠判断或处理的页面明确标为待核对。

# 4. 总体架构与职责划分

## 4.1 三条通路

```text
实时通路（保留）
采集/AudioJournal → WLK + 本地 Qwen/Whisper → SaT/Caption
                                            → 本地翻译 → Qt 字幕

知识通路（新增；不阻塞实时通路）
上传课件 → 解析/来源块 → 术语库 → 有界 ASR Context
                              ↓
Caption 源事件 → 本地事件存储 → 检索证据 → 增量笔记 → Qt 笔记页

课后通路（新增；按需运行）
课程材料 + 已保存原文快照 → 选定 harness 受限工具 → 结构化整理草稿
                                                   → 校验/发布/导出
```

图中的“最终原文”表示当前版本已确认，不表示后续永远不能纠正。音频、原文、材料是证据；笔记和 agent 压缩记忆是派生结果，不能反过来替代原始证据。

## 4.2 进程和依赖

保留 Qt、WLK 及实际使用的 MLX/llama.cpp 进程。知识任务由后台执行，首版至多一个按需启动的受管知识工作进程，承载已选定的 API/harness 及解析任务；没有启用知识功能或没有任务时，不新增启动预热和常驻轮询。模型式重型解析与实时录音错开，不再预建独立解析进程池。

知识代码保留在 `linguaflow` 内部命名空间，桌面只导入轻量协议和业务对象；重型依赖在工作入口按需导入。先检查所选 API/harness/解析包与桌面依赖是否兼容；只有版本冲突或隔离需求成立时，才增加 `.venv-knowledge`。新增进程不自动要求新增顶层产品包。不得污染 `.venv-wlk` / `.venv-mlx` 或升级其固定依赖；解释器位置统一由 `runtime_paths.py` 获取，安装和版本记录只覆盖实际采用的包。[R13–R15][R18]

知识进程默认不加载本地 LLM/视觉/embedding 大模型，不使用 GPU，不获取麦克风；这不改变用户已有 ASR/翻译设备或联网选择。解析完成后释放解析资源，任务结束后保存必要结果并关闭闲置知识资源。API 和文档解析仍有本地内存成本，应在 M0 测量，而不是承诺开启知识功能没有资源影响。

如使用独立知识进程，复用 `process_platform.py` 的平台启动与清理适配，通过小型版本化 JSONL 协议通信；不要复制 WLK 的音频准备/租用流程，也不为此重构通用进程框架。协议定义任务、录音/课程 ID、取消和资源释放责任；大文件只传校验后的相对路径和哈希，stdout 只放协议，诊断放 stderr。

## 4.3 绝不可破坏的实时约束

HTTP 请求、PDF 解析、embedding、数据库大事务不得进入 `caption_lock`、音频采集回调或 Qwen 解码函数。源事件接收器只做小型快照、排队与状态更新；持久化由专门写入器完成。

知识队列压力过大时，允许合并同一字幕的派生任务、标记“笔记待同步”，并在后续从已保存原文快照重新对账。不能通过丢弃已接受的音频或阻塞音频输入给知识任务腾空间。笔记失败只降低笔记功能，不使录音失败。

停止录音沿用现有本地收尾和保存逻辑；云端笔记不纳入录音停止的必等条件。关闭应用前只要求本地任务和已收到结果安全落盘；未完成任务下次打开应用恢复，不承诺应用关闭后仍在后台工作。

# 5. 目标 1：内存与显存优化

## 5.1 P0：消除累计前缀重复存储

目前 `CaptionMapper.fixed` 保存 `(caption_id, end, text[:end])`，校验时逐条执行 `text.startswith(prefix)`。如果有 n 条长度近似 c 的定稿字幕，仅前缀字符数约为 `c × n × (n + 1) / 2`，随字幕数平方增长。[R5]

例如每条 64 个字符、2,000 条字幕，会保存约 1.28 亿个前缀字符；这是理论字符数量，不是实际测得的 RSS。字符编码宽度、Python 对象开销、真实分句和回退行为都会影响字节数，但不会改变重复存储的结构问题。

建议只保留一份上次全文与每行结束位置，不保存每行累计全文。新文本改变时，计算一次旧全文与新全文的最长公共前缀位置；同时考虑 `stable_end` 回退，通过结束位置二分找出仍可保留的定稿行。无文本变化时复用已知结果，避免心跳反复扫描全文。

```python
# 设计伪代码：保留行身份和位置，不保留累计字符串。
fixed_rows = [(caption_id, end_offset), ...]
common_end = longest_common_prefix(old_text, new_text)
valid_end = min(common_end, new_stable_end)
keep = bisect_right(fixed_end_offsets, valid_end)
# 然后继续执行现有的最后一行语义重评估、历史纠正和重切规则。
```

不能直接删掉旧前缀校验后假定历史不变。应对同一组输入快照做旧/新实现差分测试，检查 source、ID、ready、final、segmentation_revision 和 tombstone 一致。全文纠正、稳定范围回退、停顿后续接、中文、标点改写和空行删除都要覆盖。

## 5.2 P1：量化内存，而不是只看一个峰值

新增每会话资源采样：UI 与自有子进程树 RSS；平台可用时记录 USS/私有提交；CUDA allocated、reserved、峰值；外部 llama.cpp 进程及驱动层占用；MLX active/peak 与系统内存压力。不同口径分列，不把 Apple 统一内存和进程 RSS 简单相加。

`wlk_worker.py` 已输出 `max_memory_allocated()`，但所检查路径未见每会话重置峰值；应在本次模型加载前重置统计，同时保留“加载峰值”和“稳态峰值”两个阶段。上下文复用、文件缓存和预热状态必须写入 benchmark manifest。[R7][R11]

录音进行到 10/30/60/120 分钟时采样，再记录停止后的 1/10/60 秒。只有增长趋势和归属明确后，才决定清理缓存、销毁空闲进程或替换模型。

## 5.3 P1：减少历史数据的重复复制

`RecordingSaver.submit()` 会复制全量 Caption 后再合并待保存任务；现有自动保存约每 1.5 秒触发。这不是直接证明内存泄漏，但会随课堂增长增加分配和序列化成本。[R10][R12]

先增加计时与复制字节估算，再考虑在准备快照前合并请求、只在源/译文有效变化时保存，以及后续的增量日志加周期快照。必须继续保持不可变快照、单写者、会话归属和失败恢复，不能让保存线程直接读 UI 正在修改的对象。

翻译缓存已经有 512 项上限，不应误报为无限缓存。可补充字节上限，因为缓存键含原文和上下文。新的检索缓存、页面图像、agent 检查点也应限字节、限历史，而不只限条目。[R9]

## 5.4 P2：有条件地做模型与窗口实验

现有 PyTorch Qwen 已使用合适设备精度、SDPA、batch=1；Mac 已有 MLX 4-bit；翻译已有 GGUF 路线。不能把这些作为本次“新增”成果。[R1][R3][R8]

优先保持当前识别质量，评估让新知识功能完全走 API 的成本。再分别测试 Qwen 0.6B/1.7B、已支持的量化后端、翻译放 CPU 或关闭等明确配置。低内存档必须明确提示可能增加延迟或影响准确率，不在后台静默换模型。

30 秒 16 kHz float32 单声道 PCM 约 1.83 MiB，含 5 秒额外范围约 2.14 MiB；这不能解释数 GiB 的总占用。`np.concatenate` 和跨进程 base64 确有复制，但优先级低于模型状态、累计前缀和长历史对象。改用 ring buffer/共享内存应有 profiling 依据。[R3][R8]

空闲 WLK 预热进程保留 30 分钟是现有体验选择，本轮不增加“省内存”模式或自动改动其生命周期。只有实测证明现有策略构成使用障碍时，再独立评估最小调整；不能在录音中杀进程。`empty_cache()` 不能替代释放活跃模型与框架资源。[R1][R7]

# 6. 目标 2：提交逻辑与实时体验

## 6.1 区分五个时刻

本文的“提交”指字幕/翻译状态提交，不是 Git commit。建议诊断分别统计：首次可见原文、可用于初译的原文、ASR 确认、SaT 边界确认、当前版本最终译文。现有代码已经区分了其中多个状态，UI 应展示真实状态，而不是为了显得快把草稿叫作定稿。[R4–R7]

当前默认策略包括：ASR 至少 3 轮一致、4 秒真实音频推进、保留尾部 4 个文本单元；SaT 边界需多次有效观察及后续已确认文本；尾部初译还有 lookahead。它们存在叠加延迟，但不能简单把所有阈值降低到零。[R4][R5]

## 6.2 推荐试验，不直接改默认值

保留准确优先基线，增加内部实验策略：缩短首次可见草稿等待、给可修订初译设置合理节流、按语言评估 holdback 单元、减少未改变快照的重复分句与发布。`process_iter()` 已按上一轮计算耗时自适应节流，不必再照搬一套同样的限速器。[R3]

界面可继续即时替换草稿，但采用稳定行身份与保留阅读位置，避免每次更新整页闪动。已有“未定稿较淡、定稿恢复正常”机制应复用。笔记栏的更新频率独立于字幕，不随每个词抖动。[R12]

以下规则必须保留：窗口容量满不等于一句结束；标点不等于声学确认；短 VAD 静音不等于永远定稿；同一 PCM 被重复解码不算新的确认轮次；后文纠正必须允许撤回旧结果。[R3–R5]

## 6.3 评估方法

使用冻结的同一音频、模型、设备和前处理，一次只改变一个策略因素。分别统计首条可见延迟、稳定文本延迟、初译延迟、修订频率、撤回跨度、重复/漏词、停止收尾、最终 WER/CER。按真实语音结束点计算延迟，不把模型启动时间混在一起。

技术词、人名、长句、中英混说、重复内容、短停顿和 30 秒跨窗是重点场景。真实课堂独立人工稿用于验收；仓库的合成英文 WER=0 只能作为回归。速度提升伴随术语错插或漏词增加时，不应作为默认策略发布。

# 7. 目标 3：课件解析与 Qwen 术语增强

## 7.1 产品流程

用户为录音选择课程并上传 PDF/PPTX。程序先生成页/幻灯片预览、章节大纲和候选术语；用户可勾选、删除、添加别名，随后点击启用增强。解析尚未完成时仍可开始普通转写；界面明确“术语尚未启用”，不能假装已加载。

第一版聚焦 PDF/PPTX；TXT/Markdown 如能复用同一来源模型且有实际使用需求再加入，DOCX 不列为必需交付。扫描或图片页使用已验证的 OCR/视觉能力，缺少该能力时保留页面并标明未解析。云端仅接收已授权片段或必要页，不上传原始录音；未配置云端时仍可浏览本地原生文本和手动维护术语。

## 7.2 分层解析

第一层读取原生文本与结构，保留 PDF 物理页或 PPTX 幻灯片、标题、正文和可取得的位置；缺失表格/公式内容应可见。若真实材料比较后选用 Docling，将其文档表示适配为同一 `DocumentBlock`，不另建平行业务模型，也不只保留扁平 Markdown。[E9]

第二层核对解析质量。已有文字层的内容在本地提取，不为简单文字读取重复调用云 API；模型只处理必要的术语、大纲或语义任务。扫描页、图表、公式或明确遗漏页才按授权渲染并请求视觉补全；优先用可复现规则和解析结果识别遗漏，必要时由预览中选中的页面触发。限制资源和请求，不把整份可复制课件逐页重做视觉识别。

第三层让文本模型输出结构化章节与术语。返回结果必须能定位到输入的 block、原文片段或页面图像区域。图像推断与直接文字抽取分开标记；无法确认的公式保持图片/原式并标“需核对”，不自动补写证明。

## 7.3 统一来源模型

```text
DocumentVersion
  document_id, content_sha256, parser_version, original_name, status

DocumentBlock
  block_id, document_id, document_version, block_type
  page_number?, slide_number?, paragraph_id?, char_start?, char_end?
  text, bbox?, extraction_method, quality_flags

Term
  term_id, canonical, aliases[], language, category
  evidence_refs[], extraction_status, user_approved, disabled
```

UI 页码/幻灯片编号从 1 开始；以后支持 DOCX 时，未渲染分页使用段落/block 引用，不虚构页码。解析缓存键包含文件哈希、解析器版本及影响结果的配置；模型抽取缓存另包含来源版本、输入范围、供应商/模型 ID、提示词和输出 schema 版本。修改同名文件建立新版本，不能复用旧引用；缓存只复用成功且可校验结果，不能保证所有失败重试均免计费。

`extraction_status` 是可验证状态，例如 directly_grounded / visually_inferred / needs_review，而不是未经校准的“95% 正确概率”。别名要区分原文出现的别名、用户输入的别名和模型提出的候选别名，后者不可默认视为课件事实。

## 7.4 术语提取和选择

抽取偏向容易听错的专有名词、缩写、算法名、变量读法、人名、课程特有表达，例如 softmax、backpropagation、Bayes、ELBO；不把整段解释或泛词作为热词。英文术语保留原词，中文释义主要服务笔记，不必全部拼进 ASR context。

先从本次选中材料抽取候选，再生成小的会话术语集合，不要求先建完整学期术语库。20–50 个术语、约 256–512 个实际 tokenizer token 仅为实验起点；根据相关/无关词表对照确定内部上限。首版只在启动前按选中材料与术语审核结果编译，录音中不因当前页或新字幕改变快照。

不自动扩大到整学期全部术语。错误或无关的提示可能诱导未说出的词，术语更多不必然更准确。词表必须有关闭入口，并记录当前生效版本以支持 A/B 回放。

## 7.5 共享静态快照与两端适配

同一份静态快照保存所选材料版本、已审核术语、编译文本及其哈希；编译和选词业务保持一份，后端只适配参数。PyTorch `Qwen3ASRModel.transcribe()` 接受 `context`，当前应用传空字符串；本机安装的 Qwen3-ASR 0.0.6 接口也已静态核查。[R3][E12]

Mac 应用尚未传入提示，但固定 `mlx-audio==0.5.6` 的 Qwen `generate()` 已提供 `system_prompt` 和 `hotwords`；后者合入系统提示，最终进入模型输入。首版优先将共享快照的编译文本传入 `system_prompt`，不在 MLX 另写一套选词或提示编译规则，也不重复同时传同一词表。不要传未经验证的 `context=`，该源码的 `**kwargs` 可能忽略未知参数。[R8][R17][E16]

```python
# 接入形态示意；snapshot 由会话配置固定，不在解码时调用云 API。
snapshot = session_context_snapshot
result = model.transcribe(
    (audio, 16000),
    language=canonical,
    context=snapshot.text,
)[0].text

# MLX 适配示意；经 MLXClient 启动协议传入同一静态快照。
result = mlx_model.generate(
    pcm, language=canonical, system_prompt=snapshot.text,
    temperature=0., max_tokens=512, prefill_step_size=256, verbose=False,
)
```

编译为简短主题与术语清单，例如“Topic: neural network optimization. Terms: softmax; backpropagation; stochastic gradient descent; Adam; learning rate.” 不伪造对话，不把笔记答案当待识别原文。PyTorch `context` 和 MLX 提示均不能宣传成带权重的强制词典；MLX 的 `hotwords` 名称也不改变其提示词机制。[E16]

启动前固定 `context_version`，随录音保存完整生效快照；当前会话始终使用它。迟到的解析结果或录音中修改的词表提示下次会话生效，暂停/继续也不改变当前快照。空快照沿用无提示基线。快照哈希和实际参数到达模型的诊断用于开发核查，普通界面只显示是否生效及所选术语。

静态 MLX 接入属于首批产品闭环，优先完成当前 Mac 的 Apple GPU 文件推理验收；Windows PyTorch 保持同一业务实现并分别验证。源码提供入口不等于本项目已启用、质量改善或 GPU 测试通过。真实麦克风/系统音频测试仍受 AGENTS.md 中现有录音保护约束，不静默回退 CPU。[R15]

## 7.6 动态词表：后续按实际需求评估

动态模式需新增 `asr_context.propose` 控制消息及 `asr_context.applied` 回执。先暂存新词表，到显式新话语边界应用；一次重叠窗口及其稳定性比较使用同一个版本。不能把更换提示后的同一段 PCM 结果混入旧的多轮一致证据，也不应为应用新提示强行截断一句话。

仅在真实课堂证明静态词表不足时，再实现上述边界切换和回执；不因已有协议设计就提前增加入口。静态 Mac 支持不依赖本阶段完成。

## 7.7 术语增强的验收

首版对同一批音频比较无提示、人工静态词表、自动提取并审核的静态词表及故意无关词表；动态模式实现后独立评价。报告总体 WER/CER、术语召回、错误术语插入、词表长度、推理耗时与资源占用，两端分别记录。不能只展示修好了几个单词。

先建立真实课程基线，依据样本量、错误类型和可接受的阅读影响确定门槛；不预设召回必增 5 个百分点或 WER 可劣化 0.5 个百分点。使用独立人工参考稿，提示只来自合法材料或事先准备的人工词表，不从答案抽词。小样本报告逐条改善与变差，证据不足时不默认开启增强、不宣布泛化收益。

# 8. 目标 4：有来源、可修订的课堂笔记

## 8.1 输出不应是一段滚动摘要

建议按课件章节维护笔记，包含概念与定义、老师新增的解释、示例、公式、明确提出的问题，以及材料中出现但本次尚未讲到的内容。每条笔记分别标记“课件内容”“课堂讲述”“模型补充”；默认不生成无来源的补充。

例如，一个 softmax 章节可以显示课件定义及页码、老师针对数值稳定性的补充及录音范围、学生标记的疑问。不能因为课件写了某一结论就说“老师本节强调”，也不能未经明确证据标为“考试重点”。

## 8.2 原文和课件分别是证据

首版只把通过现有 `source_is_final()` 的当前原文作为正式笔记证据，避免翻译等待或翻译错误影响内容整理。中文笔记可以直接从英文原文生成，本地译文只作辅助展示，不作为唯一事实来源。[R6]

正式发布还须满足 9.2 的成功保存条件；确认状态与保存状态分别判断，不能将 final 当成已经落盘。

即便如此，后续 ASR 纠正或 SaT 重切仍会让旧的定稿失效；必须记录来源版本并撤回依赖。旧字幕合并删除时，现有 mapper 会发送 `source=''` 的事件，知识模块应视为 tombstone，而不是忽略为空文本。[R5]

## 8.3 事件适配与去重

录音沿用 `Library.create()` 已生成并保存在 `session.json` 的 `session.id`，不再新建平行身份；caption ID 只在该录音内有效。事件桥集中生成并持久化 `source_revision` 与录音内 `event_seq`，重启后继续递增，不让 UI、worker 和知识库各自计数。源指纹包含 source、language、segmentation_revision；确认/删除状态另参与版本判断，时间位置单独更新。译文变化不重新调用笔记模型。[R16]

```json
{
  "schema_version": 1,
  "type": "caption.source_changed",
  "session_id": "session-uuid",
  "worker_epoch": "lease-uuid",
  "event_seq": 184,
  "caption_id": 27,
  "source_revision": 6,
  "source_fingerprint": "sha256:...",
  "segmentation_revision": 3,
  "source": "Subtract the maximum before exponentiation.",
  "language": "en",
  "start": 302.4,
  "end": 307.1,
  "source_final": true,
  "asr_final": true,
  "boundary_final": true,
  "deleted": false
}
```

`source_final` 使用现有 `source_is_final()`；知识侧版本由一个业务入口维护，不直接照搬含位置/展示状态变化的 `Caption.revision`。`worker_epoch` 绑定当前会话租约，知识任务另带自己的运行代次；旧租约和旧任务结果都不得发布。文字 A → B → A 仍产生更高版本，不能仅凭相同哈希放行旧响应。final 被重新打开时立即作废其正式证据资格，空原文视为删除；重启全量对账时，旧库存在而权威快照缺少的 ID 也要作废。[R6][R7]

接收事件并不表示录音已成功保存。事件桥还消费现有后台保存的成功回执，按快照中的原文、语言、确认和切分字段确认可持久发布的来源；不另写一套录音保存线程，不把未知新字段塞进旧 Caption 格式。完整恢复规则见 9.2。

## 8.4 增量更新流程

源事件先更新状态和受影响章节，模型生成随后执行。普通新增内容短时合批，但不设“三条字幕才可处理”的硬门槛；首轮可试验 30 秒合批窗口，并在最早待处理来源已确认且成功保存满 60 秒时调度少量内容。时间为内部试验起点，M0–M4 依据真实总延迟校准，不展示为普通用户设置，也不承诺断网、限流或模型繁忙时必在期限内完成。

来源纠正、删除或重新打开立即标记相关 AI 条目 stale，不等待合批数量；满足证据条件后优先重建。主题切换、停止后的原文成功保存、用户请求更新可触发补齐。没有新证据时不常驻调用模型。调度使用已有任务状态与可取消定时机制，不增加与字幕循环同频的独立服务。

每录音最多一个笔记生成任务；排队的新事件合并到下一批。每批固定证据高水位和实际受影响范围，输入包含相关原始证据、该范围内旧 AI 条目及可引用材料。模型返回 NotePatch，不替换整本笔记。

持续新增讲述不得令所有在途任务无限重启：仅追加新证据时，当前任务可发布到其高水位，但必须保留“还有新内容待处理”状态；改变本任务输入证据、用户内容或材料关联时拒绝旧结果。不能把一次旧批次完成显示为整节课已同步。

```text
聚合源事件 → 找出受影响章节 → 检索原始证据
  → LLM 生成 NotePatch → schema / 来源 / 版本校验
  → 单事务提交 → 发布增量 UI 更新
```

不要反复“总结上一轮摘要 + 新文本”而不保留原始证据，这会让错误累积且无法局部纠正。长课堂用章节层级和证据检索控制上下文，而不是永久扩展聊天历史。

## 8.5 来源依赖与原子发布

```text
NoteItem
  note_id, section_id, kind, text, origin, status
  evidence_refs[], user_locked, note_revision

EvidenceRef
  source_type = document_block | caption
  source_id, source_version, fingerprint
  page_or_slide?, audio_start?, audio_end?, quote?

NotePatch
  job_id, base_notes_version, input_generation, affected_section_ids[]
  processed_through_event_seq
  upserts[], delete_note_ids[], unresolved_questions[]
```

保留反向依赖索引处理被引用 caption/block 的修改、删除或版本替换；同时记录每批使用的证据范围和相关章节。新增讲述也会使相关章节待核对，不只监听已引用对象变化。已知章节映射和本批检索命中共同确定范围；暂时无法归类的新增证据保持待处理，不能丢弃。

例如旧笔记引用“作业周五交”，随后老师说“更正为周一”，即使旧字幕没有改，新增证据也必须进入相关事项的核对批次。模型补丁要重新评估该范围内旧 AI 条目，明确保留、修订、撤回或列出冲突；不能只追加新条目。缺乏明确更正关系时并列来源，不擅自选取日期。检索范围之外的旧笔记不能由本批任意删除。

发布事务核对任务/录音代次、base_notes_version、全部实际输入来源版本及已保存资格；笔记、引用索引和处理高水位一并提交。输入或用户内容变更则拒绝旧结果。无关章节或高水位后的纯追加不一律作废在途任务，但未处理事件和待核对状态必须保留。新增证据已使相关章节待核对时，旧批次不能将其清为当前全部有效；待后续核对完成再更新状态。

job_id、输入版本、允许修改的范围和处理高水位由应用生成并校验，模型只能提出该范围内的条目修改，不能自行推进版本或声明事件已处理。未归类、未保存或尚未核对的来源保留显式待处理记录；高水位只是本批输入边界，不证明所有更早事件已经完成，不能用它吞掉遗漏。发布时与这些记录一并维护，持续追加测试要确认最终无来源被跳过。

用户手写内容与 AI 内容分层保存。用户编辑 AI 条目后立即归为受保护用户内容，默认不再允许自动覆盖；只有用户明确恢复自动更新才解除保护。来源失效仍可提示并提出修订建议，不改写用户文本。删除补丁限本批范围内未受保护的 AI 条目，课件与讲述冲突并列来源和待核对标记。

## 8.6 引用校验不是单一判断

第一层检查引用对象存在、属于当前课程、版本正确、页码/范围有效。第二层检查引用原文片段确实包含抽取内容。第三层通过人工抽样或独立评估判断“证据是否真的支持笔记结论”。前两层能程序化，不代表已经解决第三层。

Qwen 当前词时间戳为估计值；录音引用应显示为近似片段位置，不能宣传逐词精密定位。需要更精确对齐时，可在课后单独运行已验证的 forced aligner，不将额外模型设为实时必需项。[R1][E12]

# 9. 工作流、持久化与 agent 工具边界

## 9.1 三类业务任务

`ingest_material`：校验文件 → 建立内容版本 → 结构化解析 → 难页视觉补全 → 术语/大纲抽取 → 来源校验 → 用户审核 → 发布材料版本与词表。

`update_notes`：固定事件高水位 → 读取一致证据快照 → 检索 → 生成局部补丁 → 校验 → 条件提交 → 标记已处理；无新证据则直接结束，不为了“保持活跃”调用模型。

`finalize_session`：本地原文收尾并成功保存 → 固定课程/录音快照 → 补齐脏章节 → 可选已选定 harness 综合整理 → 校验证据 → 生成 Markdown/结构化笔记产物。

这些是业务步骤，不预先规定必须建三张图。停止录音不等待云端补齐；本地最终保存成功后才提交收尾任务。如选定其他 harness，课后步骤使用同一业务工具和发布规则，不保留两套执行路径。

## 9.2 检查点不等于业务数据库

权威数据分工如下：成功保存的 `session.json` 是跨启动录音原文入口；课程材料的原件及已发布解析版本是材料证据；业务 `state.sqlite` 管知识来源映射、任务结果、用户编辑与笔记事务；框架检查点仅记录执行进度。活跃会话的最新内存原文用于立即失效，但知识库不得成为另一套可覆盖录音文件的原文主库。

正式笔记提交前，全部录音证据必须在有效保存成功回执对应的原文快照中出现，并与当前输入版本匹配。保存期间可准备模型输入或显示明确标为未保存的草稿，但未满足保存条件时不能当成持久有效笔记、正式导出或恢复依据。保存失败保留现有有效笔记，提示等待，不清除未保存状态。[R10][R16]

重启时先验证 `session.json` 和材料版本，再比对知识来源：缺失、不同文本/确认状态/切分版本的证据及其 AI 派生条目标记失效，作废旧运行代次并从权威快照重建。即使知识库记录了 B、磁盘原文仍为 A，也不能把 B 自动写回录音或继续将 B 笔记显示为有效。若权威快照损坏，保留全部文件与用户笔记，只暂停该录音的自动知识更新并提示检查；不自行选较新数据库覆盖。有效用户笔记不因对账丢失。

如采用框架检查点，只保存 job_id、输入版本、结果引用、阶段、高水位和预算；不复制 PCM、图片、全文和整本笔记。LangGraph 默认快照可产生存储增长，应限制状态体积，不预先引入增量通道或自定义序列化优化。[E2]

按框架实际需要分配 thread_id，例如 `ingest:{document_version}:{job_id}`；仅使用检查点时才创建 `workflows.sqlite`，不把两库作为所有任务的先决条件。两者不是跨库原子事务，业务结果以幂等 job_id 和成功事务为准：“业务已提交、checkpoint 未完成”恢复时复用结果，不重复发布；“checkpoint 完成、来源已失效”拒绝旧产物。任务阶段不由两套状态机互相推测。

如采用图编排，节点尽量细分到一次外部调用或一个确定性变换；关键阶段选择同步检查点。任何可能重放的写操作先检查幂等记录，业务事务与节点完成分开验证。检查点不会使网络 API 自动变成 exactly-once：网络超时但服务端已计费时，重试仍可能重复计费。[E2]

## 9.3 数据保留和文件工作区

```text
录音根目录/
  课程文件夹/
    .agentscribe/
      course.json
      materials/<content_hash>/original
      materials/<content_hash>/<parse_version>/blocks.json
    录音名称/
      录音.wav
      session.json
      定稿.txt / 定稿.srt
      knowledge/
        manifest.json
        state.sqlite
        workflows.sqlite    # 仅采用框架检查点时存在
        notes.md
        exports/
```

这是新增目录，旧格式不需要迁移。现有 `Library.refresh()` 已跳过点开头目录且不递归录音内部，先验证该布局不会出现伪录音/伪文件夹，不为目录外观修改扫描。所选课程文件夹有持久 UUID 时复用它；默认 inbox 标识或由外部目录路径推导的标识不能当跨目录稳定 course_id，必要时仅在 course.json 中保存一次课程 UUID。manifest 记录实际关联及版本，路径只作定位信息。材料先在课程内保存一份，跨课程全局去重后置。[R16]

原文恢复遵守 9.2；中间事件丢失可由最终成功保存快照重建，不要求为每个草稿永久保存事件日志。原有保存尾部丢失风险没有因此消失，不能宣称零丢失。旧程序应能照常读取原有字幕字段并忽略 knowledge 目录。[R12]

缓存采用内部容量与保留期限，不增加普通设置。只清理可重建页图、临时响应和完成任务的非必要检查点；保留恢复所需状态、模型/提示词版本、输入与结果哈希及用量。原课件、录音和用户笔记不按缓存策略删除。

## 9.4 文件移动、删除与后台任务

首版目录移动不自动改变语义课程关联：录音移到其他文件夹仍按原 course_id 解析材料，应用显示其实际关联；重新关联课程作为用户明确操作，建立新关联版本并使受影响 AI 笔记待核对。课程目录改名/移动通过持久 course_id 及当前库内可校验的定位信息重定位，不自动搬迁其他录音或重命名原材料。

沿用 `can_edit_library`、后台保存等待和录音锁；扩展其检查范围到受影响知识任务与数据库句柄。库操作前暂停新任务、作废在途发布权限、等待本地写入结束并关闭受影响连接和资源，之后才能移动目录。取消远端请求不必无限等待其返回，迟到结果按代次拒绝；本地句柄未释放或保存失败时明确阻止操作，保留未保存数据，不能用强制删除解决。

录音进入最近删除时，knowledge 和用户笔记随同一目录保留，任务停止；恢复后以原 ID 和权威来源重新对账。课程进入最近删除时，留在其他目录的关联录音继续可读，其材料引用显示暂不可用并暂停依赖该来源的自动任务；课程恢复后重新解析关联。永久删除共享材料前列出仍引用它的录音，不能静默删除其来源、扩大删除范围或偷偷复制用户明确要删除的原件；存在引用时先阻止直接永久删除，按用户明确选择保留、解除关联或取消。材料暂不可用不等于获准删除用户笔记。

外部文件管理器改名/移动/删除后，下一次刷新和任务发布都要重新核验稳定 ID 与受控路径；无法定位时停止该来源任务，不写入同名替代目录。失败恢复测试包含 Windows 打开 SQLite 连接及 WAL 文件时的移动/删除，不能仅用路径字符串测试证明安全。

## 9.5 选定 harness 的最小权限工具集

建议仅提供 `search_course_materials`、`read_material_blocks`、`read_transcript_spans`、`read_section_notes`、`propose_note_patch`。工具内部按 course_id/session_id 做范围检查，限制返回条数和 token；不提供任意 SQL、任意路径读取或通用网络请求。

材料只读；正式笔记只能通过校验后的 `propose_note_patch` 发布。允许 agent 写自己的临时草稿区，但不直接操作 WAV、`session.json`、API key、原始材料或用户手写内容。

Deep Agents 的本地文件后端与本地 shell 是不同能力；设置根目录也不应等同于操作系统沙箱。默认不配置 LocalShellBackend、不开放 execute/eval、不允许自动安装包或修改自身 skill。内置文件工具白名单、权限规则和自定义工具的检查都要做；官方文档说明文件权限并不覆盖任意 shell/custom tool 行为。[E4][E14]

第一版不开放子代理。确有并行章节整理需求后，才开放固定种类、固定数量和独立预算的子代理，并对子代理复用同样的权限约束。不要把 `subagents=[]` 当成一定能关闭所有默认代理的跨版本契约；使用锁定版本文档规定的配置，并在测试中检查实际工具清单。[E15]

# 10. API 适配、检索与资源预算

## 10.1 模型按能力分工

以 DeepSeek 为首个实际接入对象，模型名称和端点集中在一个适配配置中；抽取、笔记和 harness 复用已验证客户端，不各写一套 HTTP/重试逻辑。先用同一供应商完成能完成的任务，只有实际视觉或其他能力缺口时才增加第二适配，不预建通用供应商插件/路由平台。“OpenAI-compatible”不自动保证所有模型、schema、流式和工具调用组合兼容。[E3]

```text
ApiConfig                  # 集中配置，凭据只存引用
  provider, endpoint, text_model_id, visual_model_id?, credential_ref

VerifiedCapabilities       # 锁定版本的测试记录，不是通用路由接口
  actual_model_id, text, image_input, tool_calling, structured_output
  streaming, cancellation_behavior, usage_reporting
```

在 M0 做小样本探针：中英文、合法/非法结构化输出、未知字段、完整工具往返、流式中断、图像、超时、取消、限流与 usage；在实际供应商/模型/API 格式组合上验证，不只检查包能否导入。服务端中止与客户端丢弃结果分开记录。缺少视觉时显示未解析页并保留手工补充，缺少工具调用时不得宣称 harness 已验收。

供应商官方 API 说明是能力核查的主要依据，框架适配页和版本源码也要核查；两者不一致时以实际调用记录定结论。2026-10-07 官方 DeepSeek 已有视觉输入文档，不能根据旧适配能力表先断言它必须配第二视觉供应商；本次未调用付费 API，仍不构成账号或适配验收。[E17][E18]

首版配置仅覆盖凭据、已验证模型和是否启用对应云用途；超时、并发、token 预算和检查点策略用集中内部默认值。缺失配置不会改变本地 ASR/翻译选择，不将能力探针表变成用户要逐项勾选的设置页。

## 10.2 检索先做小而可靠

按课程和文档版本隔离检索。第一版使用标题/章节、关键词、原文短语和页码范围排序；显式选中的当前幻灯片优先，但只是相关性信号，不作为老师已经讲过的事实。

英文和技术标识符可用词级检索；中文需明确分词或字符 n-gram 策略，不能默认任意数据库分词器就能正确处理中英混合术语。检索评测不过时再添加 embedding API 与小型向量索引；不默认加载本地 embedding GPU 模型或部署大型检索服务。

检索返回 block ID、原文、来源位置和版本，不只返回不可追踪的摘要。不同课程、测试答案和未授权材料不能进入同一次提示上下文。

## 10.3 建议初始预算

以下只列内部试验起点；最终限制依据真实材料、供应商能力、费用及目标硬件校准，不是官方上限或新增用户调参页。每项都应有具体资源理由，不能把任意数值当功能验收依据。

| 项目 | 建议初始限制 | 超限处理 |
| --- | --- | --- |
| 课件导入 | M0 依据实际文件及展开/渲染资源确定内部上限 | 超限说明具体原因，支持分批选页；不预设 50 MB/300 页为产品承诺 |
| 结构化解析 | 1 个重型解析任务 | 录音时可延后难页处理 |
| 视觉请求 | 同时最多 1 个 | 顺序处理、逐页显示进度和成本 |
| 文本 API | 全局最多 2 个；同录音笔记最多 1 个 | 合并增量，不堆无限任务 |
| 一次笔记输入 | 约 6,000 token 总预算 | 按章节检索，不传全文历史 |
| 活跃 ASR 术语 | 20–50 项，约 256–512 token 起测 | 按相关性截断，用户可查看生效词表 |
| 课后 agent | 最多 12 次模型请求、明确总 token 预算 | 输出已完成草稿和未完成原因 |
| 临时图片/缓存 | 内部字节上限与清理期限 | 淘汰可重建缓存，不删原文件 |

API 请求应有每次超时、任务总期限、有限次数退避与取消标记。认证/余额错误不盲目重试；临时限流根据服务端提示和剩余预算处理。取消后迟到的结果只能缓存或丢弃，不能重新发布已取消任务。

请求次数与总预算包含框架内部的压缩、工具循环、重试及后续子代理调用，不能只统计业务入口。发起前检查剩余额度和在途预留量；用量不明或响应丢失时标明费用估计的不确定性，不能承诺远端零计费。M0 核查框架回调是否能覆盖全部请求，否则该 harness 不能作为已具备硬预算的实现。

费用按供应商实际 usage 和模型价格配置估算：输入 token × 输入单价 + 输出 token × 输出单价 + 视觉/其他计价项。示例：一小时按 45 秒一次最多约 80 次批次检查，但无足够新内容时不请求模型；它不是固定账单。UI 显示本次累计量与预算，不宣称固定“几分钱一堂课”。

# 11. UI、隐私与故障体验

## 11.1 UI 增量

复用现有录音详情、主题组件和导航；第一批只增加课件预览、术语审核与清楚的生效状态，笔记阶段再增加笔记区域，不同时重排整个主界面。显示“材料待处理/部分页失败”“已启用所选术语/下次会话生效”“笔记更新至某录音位置/还有新内容待处理”，版本号、线程/任务 ID 和精确 token 上限放诊断。

笔记支持点击引用回到材料页或近似录音片段；向上阅读不强制跳回最新章节，局部更新保留阅读位置。来源失效显示“来源已变化，待核对”，不要在任务尚未运行时显示“正在核对”；单纯追加显示“有新内容待处理”。保留旧 AI 条目供核对，但不以当前有效结论导出；受保护用户内容始终保留。

模型未配置、解析未完成、API 断网、预算耗尽、笔记等待和录音本身失败要分别展示，不共用一个“识别失败”。

## 11.2 本地产品的隐私承诺需要显式更新

当前 README 写明录音与字幕不上传云端；目标 3、4 会新增上传材料和课堂原文的可选行为，因此必须更新文案，而不是复用旧承诺。[R1]

云端用途默认不启用；分别说明课件片段/必要页用于材料处理，以及课堂原文片段用于笔记，显示供应商、范围、用途和停止方式。已有有效授权在同一范围内持续有效，不对每页或每次增量重复确认；新增供应商或扩大用途/数据范围时再取得相应授权。关闭云用途立即停止新请求并作废迟到发布，本地 ASR/翻译、手动术语和已缓存材料继续可用。原始音频首版不上传。

“云用途未启用”不等于强制应用离线，不设置全局离线环境变量、不阻断用户允许的模型下载，也不恢复已经删除的严格离线开关。开始录音无需等待用户完成云端配置。

API key 用系统凭据存储，不写入 `session.json`、数据库检查点、导出文档或日志。外部追踪服务默认关闭，不能因采用 LangGraph/Deep Agents 就自动上传课堂内容。诊断导出先去除 key、绝对个人路径和默认不需要的原文。

## 11.3 文件与 prompt injection 防护

课件正文是数据，不是指令。解析器按 MIME 和文件结构检查；限制压缩展开大小、页数、图片尺寸与处理期限；禁止从课件中的链接自动抓取任意 URL，拒绝路径穿越与越界符号链接。

模型看到“忽略规则、读取密钥、上传其他文件”等内容时，不应因此获得额外工具权限。安全边界依赖工具白名单、路径/课程范围、只读证据和应用级发布校验；不能只靠一句 system prompt 或一个模型防护分类器。

MarkItDown 官方也提示其 I/O 使用宿主进程权限。即使选轻量解析器，也应调用最窄的本地转换接口并隔离不可信输入，不能把“只是文档转换”当作无需权限设计的理由。[E10]

## 11.4 故障矩阵

| 故障 | 对用户的影响 | 必须保持的行为 |
| --- | --- | --- |
| API 断网/限流 | 新笔记延迟 | 录音、字幕、本地保存继续；任务可恢复 |
| 课件部分页失败 | 术语与笔记来源不完整 | 标明失败页，不假装整份解析成功 |
| 源字幕被纠正/删除，或新证据需核对旧结论 | 相关笔记失效或待核对 | 来源变化立即标记；新增讲述进入相关范围核对，旧批次不清除待处理状态 |
| 知识进程崩溃 | 当前云任务中断 | 重启后对账与恢复；不终止音频进程 |
| 磁盘不足 | 新知识结果无法保存 | 停止新增知识任务并明确报警；沿用录音保存错误处理 |
| 移动/删除时知识任务或数据库仍占用目录 | 文件库操作暂不可完成 | 先撤销发布权限、完成本地写入并释放句柄，失败时保留数据并说明原因 |
| 用户取消/退出 | 云任务可能未完成 | 本地记录状态；不承诺远端请求必定未计费 |

## 14.1 测试分层

单元层：解析位置和缓存配置键、术语编译/截断、混合语言、两端参数适配、源指纹和确认状态、持久单调版本、A→B→A、tombstone、NotePatch 范围与编辑后自动保护。使用 mock API 覆盖空输出、额外字段、截断 JSON、错误引用、重复 ID、异常长输出。参数到达模拟模型只证明调用契约，不能证明识别改善。

任务层：在解析后、模型返回后、业务事务及实际采用的 checkpoint 前后注入中断。覆盖“知识库 B / 保存原文 A”、权威快照损坏、缺失 caption、旧批次完成时有新增讲述和仅一条待处理原文；恢复不覆盖录音、不重复发布、不把未完成显示成功。用“周五交→更正周一”检验新增证据能核对旧 AI 条目。测试外部调用重试与全部框架内部计费，明确不能保证 exactly-once。

文件库层：知识任务在途、SQLite/WAL 打开、保存失败、跨文件夹移动、课程暂不可用、最近删除/恢复、永久删除仍被引用材料、外部移动及旧程序读回。失败时保留用户原件/笔记和未保存状态，不能仅验证正常关闭后的目录操作。

实时回归层：沿用 `scripts/test_no_audio.py` 入口及已有文件回放方式，不擅自打开麦克风或播放个人课堂录音。现有 CI 的模拟通过不等于 GPU、实际设备或两小时课堂验收。[R14]

长会话层：冻结 30/60/120 分钟样本，先做无模型的字幕事件重放，再在用户目标硬件单独验证真实推理。包含录音暂停继续、窗口跨越、长静音、重复内容、断网、知识进程重启和最终导出。

## 14.2 建议验收表

正确性约束直接验收；质量、耗时和资源门槛根据真实基线与样本量确定后固定。所有相对性能比较使用同硬件、同模型、同音频、同前处理和运行状态。不以未经校准的 5 个百分点、0.5 个百分点、95% 或 10% 数字替代实际质量判断。

| 维度 | 建议门槛 | 判定方式 |
| --- | --- | --- |
| 原实时链路隔离 | 云端全断网时录音、原文与本地保存不受阻 | 故障注入；核对完整 PCM 与字幕 |
| Mapper 内存 | 固定行结构不保留累计全文；数据量翻倍不出现对应平方级字符串增长 | 对象统计与 1k/2k/4k 行重放 |
| 功能关闭兼容性 | 字幕状态、导出和现有回归不劣化 | 固定输入差分；全套既有测试 |
| 开启知识功能影响 | 核查实时流程是否出现使用障碍，耗时/资源界限由基线确定 | 同条件报告 ASR 延迟分布、UI 响应、内存增长、停止收尾；不只看平均值 |
| 术语效果 | 改善足以承担错误诱导与性能成本，证据不足不默认启用 | 独立人工稿，报告总体 WER/CER、术语召回、错插及逐条变差案例 |
| 引用有效性 | 发布的引用对象、版本、范围全部合法 | 确定性校验；非法结果不得发布 |
| 引用支持性 | 对代表性样本核查结论支持性，关键错误单独判定 | 公式、否定关系、作业要求/日期等不能被总体平均通过率掩盖 |
| 修订一致性 | 修改/删除与新增冲突证据均能触发相关范围核对；旧批次不清除新待处理状态 | 乱序、重切、撤回、新更正、持续追加及重放 |
| 用户编辑 | 自动流程不覆盖锁定/个人笔记 | 事务与 UI 回归 |
| 笔记延迟 | 总延迟与剩余待处理状态真实可见，单条证据不因数量门槛永久滞留 | 从语音结束测至有效笔记，包括 ASR/SaT 确认、保存、排队和 API；异常等待另列 |
| 恢复 | 以有效权威来源重建，未保存原文不成为持久有效笔记 | 保存/业务事务/可选 checkpoint 中断与来源损坏测试 |
| 文件操作 | 打开的连接、在途任务与引用关系不破坏移动、删除及恢复 | 两平台分别验证相关操作，不扩大删除范围 |

不得为了通过门槛删除困难样本、减少重复语句或使用评测参考稿做 ASR 提示。展示改善时同时附上变差案例。静态词表、动态词表、量化、提交策略必须分别评价，避免无法归因。

## 14.3 发布、迁移与回滚

新增知识功能默认关闭；旧录音无需转换即可浏览。新 schema 有明确版本，迁移前备份，数据库迁移失败只禁用知识功能，不损坏已有 WAV 和 `session.json`。

先在授权测试课程验收材料与静态词表，MLX 与 PyTorch 按各自证据开放；再交付可修订笔记，动态上下文仍后置。锁定实际采用的依赖、模型 ID、解析器、prompt 和 schema 版本，升级模型要重跑相关质量检查。Mac 源码接口、模拟平台和 Windows 测试都不能代替 Apple GPU 实际推理。

平台分支检查通过后由用户审核完整待合并范围，再合并 main；合并不等于发布，也不要求两平台同发。不擅自创建分支、更新应用版本、移动标签或推送；实际发布遵守 AGENTS.md 的统一版本与不可变标签规则，列清平台、设备、验证及已知限制。[R15]

回滚时保留新增知识目录供以后恢复，但旧程序必须忽略它；不能清除用户原始课件和手写笔记。导出 Markdown 是可阅读产物，JSON/数据库是可重建和继续编辑的结构化产物，两者用途不同。

# 15. 风险与最终建议

主要风险并非“缺少足够聪明的 agent”，而是模型结果和实时修订之间的时序、课件解析缺失、错误术语诱导、来源失效、框架状态膨胀以及跨环境依赖冲突。它们需要显式协议和测试，不能交给 prompt 自行维持。

现成 harness 可以明显减少执行循环、工具管理和长任务上下文代码，但不会自动知道一条字幕被撤回后哪段课堂笔记应该重做。这部分应成为 AgentScribe 的核心领域层。

最终路线是：**独立修复前缀结构；提前验证 DeepSeek 与一个成熟 harness；先交付材料和共享静态术语，Mac Apple GPU 接入与验收优先；再交付有保存依据、可核对新证据的增量笔记与课后整理。** LangGraph、Docling、独立知识环境只在具体收益和兼容性成立时采用。动态提示、多代理和更多模型后端不列为首版必需项。
