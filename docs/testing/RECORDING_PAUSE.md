# 录音暂停与继续

## 行为

- 聆听期间显示“暂停”。请求暂停后暂时禁用该按钮，采集函数退出并释放设备句柄后显示“继续录音”。
- 暂停期间不采集、保存或提交新声音；已经接受的音频、字幕和翻译继续处理。
- 继续录音重新打开同一输入，写入同一份 WAV，保留模型、字幕和录音标识。暂停的墙钟时间不计入 WAV 或字幕时间轴。
- 暂停时可以停止或关闭窗口，仍会完成剩余处理和保存。设备在暂停期间断开时，恢复失败会明确报错，保留已经写入的音频。
- 启动、暂停切换、恢复切换及收尾期间禁止重复点击暂停。整个活动会话期间锁定来源、模型设置和文件库操作。

## 实现与验证方法

`CaptureControl` 使用条件变量协调采集段。暂停请求与音频写入共用锁，拒绝已经在 native read 中、但到暂停之后才返回的音频块。采集函数返回后才确认暂停，避免界面显示已暂停而声卡仍被持续读取。

`AudioJournal` 将暂停标记放在准确的 PCM 字节位置。传输线程先排空标记前的采样，再发送暂停事件，之后才能提交下一段。worker 刷新 DSP 和采样率转换的尾部，结束当前 ASR 话语，重置 VAD 并保留累计采样时钟。音频处理链重新初始化，ASR 和翻译模型继续保留。

文件并行测试还暴露了上游 formatter 的 EOF 竞争：消费者处理上一份快照期间，ASR 可能完成最后一次推理；上游恢复后直接看到任务结束并退出。兼容层在 EOF 后重新读取最终快照，再执行字幕定稿和翻译收尾。

模拟回归覆盖：

- WAV 和子进程收到的 PCM 完全一致，暂停后的迟到块被排除。
- 积压音频、连续暂停标记与恢复后的音频按顺序传递。
- 暂停期间保持会话，停止能唤醒等待线程，不重新打开采集。
- 恢复时设备异常保留暂停前 WAV，并结束工作线程。
- UI 暂停、继续、停止、关闭及迟到状态事件；暂停期间来源和文件库保持锁定。
- ASR 在快照处理期间完成时，最终文字仍被发布。

安全测试入口：

```bash
.venv/bin/python scripts/test_no_audio.py -q
```
