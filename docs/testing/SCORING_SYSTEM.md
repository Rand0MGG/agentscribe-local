# 可信的实时课堂评分系统

本系统评测整段录音经过应用实时识别后的最终字幕。没有按 20 秒或 30 秒独立识别，也不把另一识别器的转写自动当作标准答案。

## 实时回放约定

`scripts/replay_streaming.py` 使用应用的 `Session(capture_fn=文件回放)`，复用 `AudioJournal`、实际 worker、VAD、流式推理、上下文分句以及字幕修订/撤回机制。只用文件输入替代麦克风，未模拟 WASAPI 设备本身。

1. 解码原录音，保留各通道直到算术平均混为单声道，重采样为 48 kHz 浮点输入。检查媒体音频时间连续性，记录文件和解码输出 SHA256。
2. 模型就绪后，每 100 毫秒交付相应的 4800 个采样。按累计采样时钟安排交付，不能提前送入未来声音。
3. 应用自行决定处理批次、语音边界和文本修订。每个文件始终是一场连续会话，不按参考句子或固定时长重置识别器。
4. 文件结束后正常停止并等待队列排空和最终字幕。记录实际交付采样数、最大交付迟到时间和成功结束状态。

历史 `feb14-live-02` 使用的准备器拒绝超过 25 毫秒的相邻音频帧时间戳跳变；较小间隙不补静音，回放以全部解码采样的连续时间为准。另行逐帧检查发现 `feb14` 在约 568 秒和 1136 秒各有 15.034 毫秒间隙，累计 30.068 毫秒；没有丢弃解码采样。独立检查记录在 `.work/macwhinney/feb14-timestamp-audit.json`。因此该次可验证连续音频的最终文本比较，不能用于精确的媒体时间轴延迟测量。AMI 新协议已将准备器检查收紧为一个源采样的容差，并拒绝非零首时间戳；重新准备此 MacWhinney 文件会拒绝这些跳变，需要先显式处理媒体时间轴。历史运行证据保持原样。

**固定使用 1 倍速。** 当前上游推理调度依赖队列积压、真实时间和计算耗时，简单取消等待会改变处理批次，不能冒充相同实时行为。单个文件的模型加载只发生一次；文件解码在回放前完成，评分可以重复运行而不再识别。

默认验证配置固定为 Qwen3-ASR-1.7B 流式 `fast`、英文、CUDA、draft 0.5 秒、VAD endpoint 1.5 秒、SaT 自动模式/CPU、48 kHz 无增强输入、关闭翻译。它验证实际实时代码路径，不代表启用了用户当前全部设置。可通过独立 `--settings` JSON 指定配置，每次完整保存；不更改应用偏好。实验性的 `accurate` 固定窗口路径被明确排除。

## 评分如何防止误导

- **输入身份**：参考必须对应同一媒体 SHA256。完整回放的事件文件和设置必须通过哈希检查。
- **运行完整性**：缺少成功结束、未交付完整音频、运行错误、加速回放或未定稿字幕，不出分。
- **字幕状态**：按 ID 和事件顺序还原最后状态；撤回行移除，旧草稿不反复累加。不同字幕中真实重复的词保留，绝不为了降低错误率自动去重。
- **标准答案状态**：每句需有听音核对记录，并确认整段音频已听、无漏标、未参考待测输出、插话排列已检查。修改已经核对的文字或时间会撤销该句有效核对状态。
- **未核对原稿**：`wer` 保持 `null`，只能输出明确标为“未核对词差异率”的比较值。
- **人工核对参考**：允许输出 `WER = (替换 + 漏词 + 插入) / 参考词数`，并保留三类错误明细。这里的人工声明可追溯，但不是参考绝对无误的数学证明。

主评分规则固定为：统一 Unicode 和大小写，标点作为边界，保留英文缩写中的撇号，保留重复、口头纠正和填充词，不把 `2` 自动改成 `two`，不根据专业知识替换原话。CHAT 只读取说话主层，不把 `%mor` / `%gra` 语法分析计入转写；`[/]`、`[//]` 不删除真正说出的重复和修正内容；不把 `[: ...]` 编辑注释替换为实际发音。未支持的标记会进入核对清单。

另提供排除固定填充词表后的辅助指标，同时展示，不能择低报告。空参考的 WER 不定义；有参考但完全没有输出按全部漏词计。WER 可超过 100%，不会强行改写为一个“准确率”。

全局对齐使用精确 Levenshtein 动态规划，不使用启发式文本匹配。`word-errors.csv` 提供参考句子和字幕位置便于复核；存在多个等价最短对齐时，错误归属位置可能不同。所有说话人按照参考主层顺序评分，插话顺序须核对；不声称测量了说话人归属准确率。

时间指标记录首次文字出现、源文修订次数、交付延迟和实际耗时。ASR 字幕时间未经逐词校准，不作为精确的词级延迟；不会将片段结尾到字幕出现的差值包装成准确延迟。

## 本地听音校对

用普通浏览器打开 `.work/macwhinney/references/feb14.review.html`。页面引用本地原视频，没有外部脚本或上传接口。

- 播放本句前后文，编辑真实听到的词和时间。
- 缺失时间的句子会标出，并可从相邻上下文定位。
- 可补充漏标讲话；原稿误识别非讲话声音时可显式核对为空，听不清的讲话必须保留 `xxx`，不能当作静音删除。
- 点击“已听音核对这一句”；这不是批量自动认证按钮。
- 导出 JSON 保存进度，后续可导入继续。刷新前必须导出，没有自动保存。
- 确认所有句子和整段覆盖以后，用导出的参考 JSON 重新评分；音频无需再次识别。

## 运行方法

在项目目录运行。初次审计和回放输出目录应选新路径，防止覆盖之前的证据。

```powershell
# 1. 审计参考，生成校对页（已生成的目录不重复覆盖）
.venv-wlk/Scripts/python.exe scripts/evaluate_streaming.py audit --corpus media/MacWhinney --output .work/macwhinney/references

# 2. 准备整段音频，只有解码和输入格式转换
.venv-wlk/Scripts/python.exe scripts/replay_streaming.py prepare --input media/MacWhinney/feb14.mp4 --output .work/macwhinney/feb14.f32

# 3. 1 倍速完整实时回放，新目录保存每次运行
.venv/Scripts/python.exe scripts/replay_streaming.py run --prepared .work/macwhinney/feb14.f32.json --output .work/macwhinney/feb14-live-new

# 4. 评分；未核对参考只会得到差异比较
.venv/Scripts/python.exe scripts/evaluate_streaming.py score --reference .work/macwhinney/references/feb14.reference.json --run .work/macwhinney/feb14-live-new --output .work/macwhinney/feb14-score-new
```

正式参考核对完后，将第 4 步 `--reference` 换成导出的 `feb14.reviewed.reference.json`。`score.json` 为结构化结果，`score.md` 为可读报告，`word-errors.csv` 为逐词差异，`final-hypothesis.txt` 是最终字幕原文。

回放中断的目录缺少完成证据，不能评分，不能通过拼接多次半段结果修复；需要重新开始连续会话。任何数据集分数都只反映所选录音。未来调参应使用独立课程作为测试集，不在同一份答案上反复挑选最佳参数。

CHAT 解释依据：[官方 CHAT 手册](https://talkbank.org/0info/manuals/CHAT.html)。这些本地课堂媒体和衍生校对文件不纳入 Git，不随软件发布。

## 实现验证

- 项目回归测试共 71 项通过，包括精确词对齐、字幕修订和撤回、未核对参考不能获得 WER、空输出计为漏词，以及不完整或被修改的运行文件拒绝出分。
- 本地校对页面已通过浏览器实测：原视频加载和播放正常，截图布局已检查；修改已核对文本会撤销核对状态，导出 JSON 保留待核对状态。测试用文字没有写回原始参考文件。
- 六份参考均保持待核对状态；没有通过自动操作伪造人工听音核对。
