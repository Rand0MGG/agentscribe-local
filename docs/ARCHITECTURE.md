# 模块职责与依赖约束

项目按变化原因划分职责：界面布局、偏好格式、录音状态、文件管理、推理调度、翻译和音频处理分别维护。不以单个文件的行数作为拆分标准。`app.Window` 是桌面装配入口，负责连接控件和服务；业务模块不反向读取窗口属性。

## 当前边界

| 职责 | 模块 | 边界 |
| --- | --- | --- |
| 数据与导出 | `core.py` | Settings、Caption、SRT；不依赖 Qt 或模型 |
| 偏好格式 | `preferences.py` | 集中键、默认值、类型转换和历史后端别名；接受存储接口，不导入 QSettings |
| 翻译配置 | `translation_config.py` | 上下文默认值、可选范围与背景硬上限；会话、偏好、界面和规划器共用，不依赖 Qt/模型 |
| 控件适配 | `settings_binding.py`、`qt_controls.py` | 控件与偏好互转、生成独立会话配置快照；不持有 Window |
| 设置与对话框 | `workspace_widgets.py`、`management.py`、`deleted_dialog.py` | 显式传入所需控件/配置，通过信号报告操作；Qt parent 仅用于窗口归属与生命周期 |
| 界面表面与动效 | `ui_components.py`、`ui_theme.py` | 统一菜单、弹窗、渐显、可展开选项与颜色；不导入模型、会话或文件库；减少动态效果通过偏好控制 |
| 字幕浏览 | `caption_view.py` | 根据滚动位置自动跟随、平滑追踪底部、保留阅读位置与返回按钮；不改变 Caption 或推理流程 |
| 录音交互状态 | `recording_state.py` | 空闲、启动、聆听、收尾及对应按钮策略；不依赖 Qt |
| 文件库 | `library.py` | 普通本地文件夹、元数据、路径安全、迁移、最近删除；不弹窗 |
| 课程材料与上下文 | `knowledge/materials.py`、`glossary.py`、`session.py`、`schemas.py` | 原生 PDF/PPTX 解析、各格式页面快照的原子导入、课程身份、审核术语与录音快照；不导入 Qt 或模型 |
| 课件页面与解读 | `knowledge/rendering.py`、`render_document.mjs`、`render_web.py`、`readings.py` | Kit 处理 PDF/Office；独立 Qt 子进程处理离线网页、文本和图片；统一图片校验、逐页解读和覆盖，原生来源与模型解读分别表达 |
| 来源笔记 | `knowledge/storage.py`、`retrieval.py`、`files.py` | 短事务 SQLite、来源版本/保存资格、证据检索、原子发布及个人编辑保护；不承担录音文件索引 |
| 课程后台与界面 | `knowledge/client.py`、`worker.py`、`panel.py` | 一个按需创建的自有进程；界面通过消息传递数据，解析、数据库和 API 在后台运行；只在 Qt 线程展示 |
| 可选课程 API | `knowledge/api.py`、`harness.py` | 共享 DeepSeek 客户端、系统凭据、预算和受限 Deep Agents；SDK 按需导入，不进入识别运行环境 |
| 后台保存 | `recording_save.py` | 冻结字幕快照、Python 工作线程串行写入、合并待保存版本；Qt 排队信号返回录音归属、版本与成功/失败，归还任务前 join，不读取 Window |
| 库启动策略 | `library_startup.py` | 默认/指定目录、重试、迁移策略；选择目录与错误展示通过回调注入 |
| 文件锁适配 | `library_access.py` | QLockFile 的获取和检查；只使用 Library 提供的已校验路径 |
| 本地推理环境路径 | `runtime_paths.py` | 会话、模型管理和音频工具共用；不导入 Qt 或模型 |
| 后台运行环境准备 | `runtime_preparation.py` | 独立进程准备、独占交接、闲置过期和关闭；不导入 Qt 或模型库 |
| 会话传输 | `wlk_session.py` | 采集、连续音频暂存、子进程协议及停止清理 |
| 运行库预热 | `runtime_preparation.py` | 共享 CPU ONNX 运行库、单进程独占租用与空闲清理；无 Qt/模型依赖，不改变联网行为 |
| 暂停与继续 | `capture_control.py`、`journal.py` | 关闭当前采集段、等待继续、拒绝迟到音频；暂停标记与 PCM 保持同一顺序 |
| 推理装配 | `wlk_worker.py` | ASR 初始化、音频和字幕事件协调；不依赖桌面模块 |
| 模型启动协调 | `inference_startup.py` | 后端无关的 ASR / SaT 并行加载、全部就绪检查、失败与取消、资源关闭及加载任务回收 |
| Qwen 共享识别 | `qwen_accurate.py`、`asr_stability.py` | PyTorch / MLX 共用多轮确认、重叠音频窗口和完整原文；模型接口只返回字符串 |
| 字幕边界与修订 | `wlk_captions.py`、`qwen_revisions.py` | 文本边界、稳定性、版本保留；与 UI 独立 |
| 翻译调度 | `translation_queue.py`、`translation_service.py` | 合并排队版本、缓存、错误、过期结果拒绝；后端通过工厂注入 |
| 模型适配 | `backends.py`、`semantic_model.py`、`semantic_cache.py`、`runtime_compat.py` | 实际模型、SaT 本地优化缓存及上游兼容接口；按需加载依赖 |
| Mac ASR 适配 | `mlx_asr.py`、`mlx_asr_worker.py` | WLK → 独立 MLX 环境，仅传递本地 PCM；复用 Qwen 窗口、字幕和翻译流程，不访问音频设备 |
| GGUF 翻译 | `llama_translation.py` | 两端共用认证 HTTP、请求、设备确认和结果校验；复用翻译队列与提示词 |
| 本地服务与平台配置 | `llama_assets.py`、`managed_process.py`、`process_platform.py` | 固定运行组件、GGUF 校验；平台差异限于设备、路径、父进程监测和进程树清理 |
| 后台音频处理 | `audio_processing/config.py`、`pipeline.py` | 自动会话配置集中维护，worker 后台执行增益、峰值保护与重采样；没有实验室 UI 或手动参数 |
| DSP 与评测 | `audio_processing/config.py`、`pipeline.py`、`health.py`、`evaluation.py`、`ami_evaluation.py` | 保持既有独立边界；评测不借用 UI 或修改原始识别结果 |

## 必须保持的行为约束

- 偏好新增或修改从 `PREFERENCES` 开始；窗口只装配控件映射。`audio_device` 在设备枚举时恢复，`library_directory` 在窗口构建前读取，两者有不同生命周期，不强行塞进控件恢复循环。
- 严格离线选项已移除，旧偏好和历史评测快照中的 `offline` 值不再控制联网。推理入口不设置全局离线环境变量；完整的本地模型和缓存仍优先复用，加载已解析的本地文件不改变其他模块的联网行为。
- 设备元组使用 Python 内容相等比较；Qt `findData` 对相同内容的元组可能无法匹配。设备不存在时保留原选择记录并提示，不偷偷切换来源。
- 启动时通过 `automatic_audio_config()` 生成独立音频配置快照；忽略旧偏好中的手动处理参数，不再读写该偏好。处理只改变模型输入，录音仍保存原始采集 PCM。暂停/停止刷新尾部，恢复时建立新的处理器。
- 所有会话使用同一准备与租用流程；应用提前导入共享运行库，文件测试按同一流程准备。SaT 与 VAD 固定使用 CPU ONNX，不再选择独立的 ONNX CUDA 包。识别和翻译的计算设备保持独立。顺序会话结束后重置 WLK 单例并释放模型状态，清理完成后才允许下次租用，旧 Session 不得终止后续租约。取消、超时、空闲 30 分钟和退出仅清理所拥有的进程树；重复取消不重复启动清理任务。
- 各识别后端和 CPU SaT 通过同一个 `inference_startup.load_components()` 加载；两个同步工厂在后台并行执行，全部成功后才创建 VAD 状态及流式任务，避免 Transformers 加载时临时修改 Torch 默认类型影响 VAD。后端在阻塞初始化前登记可中断的子进程资源；失败、取消和会话结束先关闭这些资源，再回收加载任务，迟到资源也会立即关闭。进程内模型构造仍受父进程已有的启动期限及取消清理约束。
- CPU SaT 的 ORT 缓存准备、完整性校验与内存映射加载共用一份实现，按运行库版本、架构和本地权重标识选择，不再按操作系统名分叉；已验证 Windows ORT 1.29 与 Mac ORT 1.30。开始聆听只读取已有缓存，不转换权重；缺少完整兼容缓存时沿用原 ONNX 加载。
- 录音控件的启用/禁用统一从 `Window.set_recording_state` 设置。停止后到达的 ready/status 不得恢复成聆听状态；错误不能被进度刷新覆盖。简洁状态显示在主界面，具体日志保留在诊断与提示中。
- 修改文件库前统一经过 `can_edit_library`：活动会话检查、保存未写入的字幕、必要时检查目标目录中的录音锁。磁盘安全校验留在 Library 内部，窗口不调用其私有方法。
- ASR 提供文字与确认范围，SaT 独立管理暂定切分、首次提交和边界收尾。ASR 确认是 SaT 收尾的必要条件；只有两者均确认才能请求当前版本的最终译文。稳定尾部时钟仅触发初译；窗口容量、ASR 句号与停顿不能直接锁定字幕。
- 暂停保持会话和录音文件打开，但释放当前音频采集句柄。恢复重新打开所选设备，PCM 接续写入，时间轴只计算实际保留的采样。暂停标记必须排在已接受的音频之后；worker 刷新音频处理尾部、结束当前话语并重置 VAD，保持累计采样时钟。已有字幕和翻译继续处理，停止或关闭可唤醒暂停中的采集线程。
- `translation_context.ContextPlanner` 为首次提交、已提交原文变化、SaT 重切和双重确认建立请求快照；初译默认前 1 段，最终翻译默认前 10 段、后 1 段，背景只取已定稿原文。元数据或邻句单独变化不触发重译，不等待未来邻句。SaT 持有字幕锁并实际更新期间不启动下一项 HY 推理；等待字幕锁的发布任务不关闭翻译门，避免连续录音持续饿死翻译。队列中每段只保留最新请求，删除范围立即作废。支持 JSON 生成约束的 llama.cpp 可以合并同语言、同阶段、相邻的已排队请求，最多 4 段、合计 1200 字符；PyTorch HY 与 NLLB 逐段处理，各自使用同一规划器和消费者。批量结果按 ID 校验，发布前在字幕锁内检查整批原文、切分版本与双重确认状态；任一成员过期则拒绝整批，并重新排队仍有效的成员。发布保留当前原文、时间和定稿字段，只更新译文、错误和翻译阶段/来源；出错或取消也必须归还全部已取出的队列任务计数。
- VAD 音频张量通过 `runtime_compat.configure_vad_float32` 显式保持 Float32，避免后台半精度模型加载改变 PyTorch 全局默认类型时崩溃；见 [修复与实测记录](testing/VAD_DTYPE_FIX.md)。
- llama.cpp 在 `backends.create_translator` 按 `translation_engine` 加载，GPU 模式确认所选设备和全部模型层加载后才开始翻译，CPU 模式显式关闭 GPU 层加载。准备步骤固定下载版本并校验 SHA-256；推理阶段只读本地文件，不下载、不回退 CPU。服务绑定 127.0.0.1、使用每次会话独立认证并忽略系统代理。翻译消费结束或取消时关闭服务，独立守护进程通过 stdin 管道断开处理 worker 意外退出。
- llama.cpp 显式关闭历史请求的主机内存提示词缓存，避免沿用 b11254 的 8 GiB 默认上限。字幕版本比对包含最近 10 条经确认未变的定稿字幕和全部可修订文本；稳定前文只参与匹配，不重新分句或撤回。历史纠正先重新打开受影响行，再从该位置向前带入最多 10 条稳定字幕，不能因滑动窗口而漏掉更早的改写。
- PyTorch 与 llama.cpp 分别保存 `translation_model`、`llama_model`；引擎与设备独立。旧的 Metal 会话通过缺省引擎兼容，旧偏好迁移在 `preferences.py` 完成。提示词与默认生成参数统一维护于 `translation_models.py`。
- 翻译前文默认 10 段只用于缺失配置，已有用户选择保留。`translation_config.py` 集中背景硬上限（前 10 段、后 2 段、每段 600 字符）；规划器按用户设置选取已定稿邻段，`translation_models.py` 在提示词构建及预算处理前再次校验。误传全文或超界背景必须明确失败，不能通过分词或模型请求处理完整历史；待译原文不截断。
- 翻译上下文默认值和限制由 `translation_config.py` 定义；偏好读取时兼容整数文本、保留有效选择，损坏值恢复缺省值，超界值限制到范围内。`translation_context.py` 和模型适配入口继续执行背景校验。
- 实时翻译规划接收 `CaptionMapper` 的增量字幕，包括空原文的删除事件。规划器维护原文位置和定稿索引，只为变化段建立快照；插入、删除、位置调整及早期历史纠正更新对应索引。完整快照 `update()` 入口保留兼容。邻段变化不重译，批量相邻判断仍包含未提交草稿的位置。
- 自动保存冻结录音标识、视图代次、字幕版本和数据，在后台串行调用文件库；待写版本可合并，已开始的写入不被后来的写入越过。界面只在同一录音、同一视图且对应字幕版本成功写完时清除未保存状态。停止、导航和退出等待保存时保持 Qt 事件处理，超时或失败保留未保存内容并阻止相应操作，不销毁仍在写入的线程。
- `finished` 槽先检查发送会话，退出信号调用栈后再保存和释放；排队回调再次检查会话身份，旧会话和重复完成不能收尾新录音。磁盘写入不创建 Qt `QThread`，标准 Python 线程只通过明确排队的 Qt 信号报告完成；线程启动失败同样返回错误并保留未保存快照。
- `Session` 在用户停止或采集结束后保留 180 秒总收尾期限；重复停止、进度日志不能延长期限。超时强制结束该会话自有的推理进程树并报告失败，沿用未完整结束的保存路径，保留已经写入的录音和字幕。这是内部故障边界，不是确认门槛或新增用户选项。
- 子进程控制台与进程组参数由 `process_platform.spawn_options()` 维护，模型准备、运行库预热和本地翻译服务复用。ASR 的切窗、文本确认和重叠拼接在 `asr_stability.py` / `qwen_accurate.py`；`mlx_asr.py` 仅管理独立 MLX 解释器、加载握手、GPU 确认、PCM 请求与进程关闭，不再决定 SaT 缓存或维护另一套后台加载任务。字幕、翻译与保存没有另建平台副本。
- 默认保存目录仍为安装目录下的 `录音`；开发态使用项目下的 `录音`。自定义目录不自动混入其他库的数据。取消选目录不进入无限重试；成功打开后才记住新的路径。
- 课程后台使用 `runtime_paths.knowledge_python()` 对应的桌面环境子进程；不预热 SDK、不加载 ASR 权重、不访问音频设备。字幕回调只排队数据，成功保存回执才授予模型处理资格；打开已有录音以 `session.json` 恢复，并用当前未保存视图撤销旧资格。导航、库操作和退出先回收自有后台；迟到 UI 消息按进程代次丢弃。
- 来源版本单调增加，A→B→A 不复用旧版本。直接依赖变化使笔记失效；新讲述使用原文引句与词项检索，并复核最近两条讲述笔记。此相关性方法有边界，不保证发现任意远距离语义纠正。补丁必须逐条处理本批旧 AI 笔记，引用匹配当前已保存原文，并在同一事务检查任务、来源与笔记版本；课件独占证据不能标成老师讲述。个人编辑锁定，自动流程保留。
- 静态术语在录音开始前编译并写入 Settings；同一份有校验值的内容传到 PyTorch `context` / MLX `system_prompt`。录音中不解析课件或更改此快照。材料、笔记云用途分别默认关闭；不上传音频，不启用 LangSmith tracing，不把文档文字当工具权限或指令。
- 课程功能的桌面连接层只传消息；SDK、课件处理和来源数据库在课程子进程中运行。原有实时模块只依赖 `knowledge.schemas` / `glossary` 的术语数据规则，不依赖 worker、API、harness 或其生命周期。Whisper 开录不编译 Qwen 术语，课程后台失败不能停止录音或阻止原文/译文保存；Qwen 仍校验其明确使用的静态术语快照。库移动/删除前等待自有后台退出是文件一致性要求，保留此边界。
- Deep Agents 只持有冻结来源的检索/读取工具和内存中的待办；文件、终端、任意网络与子代理工具不向模型提供，执行层另做名称检查。框架内部模型调用同样计入预算，不配置自动供应商重试。应用持久化来源、补丁与处理进度；取消或退出后按当前保存来源重建任务，不承诺恢复未完成的框架工具循环或消除供应商重复计费。
- 每次实际模型请求前重新读取当前上传许可，覆盖直接调用和框架内部模型轮次。旧笔记按业务输入预算分批；待核对来源记录在笔记的 `pending_sources` 中，已处理原文仍可作为后续批次的新证据。课后整理逐批保存并共用请求预算，删除与修改都不能越过本批提供的旧笔记范围。草稿在开始时重编译关联课程术语，已开始的录音保留快照；重新导入可恢复损坏原件并复用有效缓存。
- 课件视觉读取顺序为原件校验 → 完整渲染 manifest 校验 → 全部页逐页读取/缓存复用 → 覆盖核对 → 笔记。空文字页和空白页不跳过。`readings.py` 将模型结果绑定原件/原生块/图片/渲染与提示版本；每页独立原子保存。`DocumentBlock.evidence_type` 区分原生文本和生成解读，后者使用独立来源 ID 与版本，引用不能冒充原文。覆盖不足时暂停课程云端笔记，不影响本地识别。
- 重新导入先写入独立的 `materials/<id>/snapshots/<snapshot>/`，校验完成后只原子替换 `course.json` 中的版本引用。退出、取消或进程被强制结束不会覆盖旧版文本、图片和资源；未发布完整/残缺目录保留，后续导入可重新构建，不自动删除用户数据。没有 `snapshot` 字段的旧材料继续按原目录读取；原件和按页阅读记录保留原位置。
- 全页读取的 `FileChecks` 仅在当前任务存活，缓存文件身份/大小/时间对应的摘要、JSON 和图片长度，不缓存图片字节。文件、阅读目录及父目录身份变化触发重新校验；每次请求仍重读许可与课程归属，前后比较来源版本。已校验缓存页不重复落盘、重写整个 SQLite 来源或逐页发送完整视图；真正的新阅读结果仍逐页保存并更新来源。
- 网页在测量和滚动截图前把 fixed/sticky 内容恢复到静态排版，保留栏内文字，避免反复遮挡各分片正文。manifest 的独立网页布局版本拒绝旧截图；使用者需重新导入旧网页，PDF/Office 渲染版本不因此改变。仍不遍历隐藏或交互状态。
- 渲染组件路径统一由 `runtime_paths.document_renderer()` 获取。Python 后台创建 Node 子进程，Node 调用固定版本独立 Kit；stdin 断开触发取消与 dispose，超时再终止自有进程树并等待退出。原件不修改，失败只清理临时派生输出。库移动和退出沿用既有后台释放路径。
- 图像上传需要新的 `material_images_cloud` 许可，旧文字许可不自动升级。请求前及结果保存前重读许可/来源；框架请求的图像也必须通过同一校验。全页读取预算按总页数确定，每页最多一请求；12 请求上限仍约束课后工具循环。PNG 容量/像素/哈希单独校验，base64 不计作文字输入。`read_material_page` 只接受冻结课程的来源 ID，图像以 user 消息交给模型，每轮最多两页；模型不能指定任意路径或 URL。
- 原生文本和完整视觉解读在来源库保留；增量笔记预算只对长视觉解读生成明确标记位置/总长度的相关摘录，并携带完整原页，避免整页因文本过长被排除。旧引用优先用于摘录定位；来源 ID/版本不变，发布引用仍必须匹配真实来源。课后读取工具可分段获取完整解读，不扩大原始字幕的截断规则。
